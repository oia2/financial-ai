# Эмулятор Daily ML

Заглушка звена ранжирования активов. Позволяет поднимать стенд платформы целиком, пока
настоящая модель не подключена.

> **Это эмулятор.** Все скоры вымышлены. Модели, рыночных данных и вычислений за ними
> нет. Каждый успешный ответ содержит `"emulated": true` — потребитель обязан это
> проверять.

---

## Что он делает

Принимает дату решения и возвращает упорядоченный список активов со скорами — в той
форме, которую впоследствии вернёт настоящая модель:

```bash
curl "localhost:8100/rankings?decision_date=2026-08-28"
```

```json
{
  "decision_date": "2026-08-28",
  "model_id": "daily-ml-emulator-v1",
  "generated_at": "2026-08-29T09:14:02Z",
  "emulated": true,
  "emulation_notice": "Значения вымышлены эмулятором Daily ML. Модели, рыночных данных и вычислений за ними нет.",
  "items": [
    { "rank": 1, "asset_id": "EQ_AST_ROSN", "price_series_id": "EQ_PRS_ROSN", "score": "0.9091" }
  ]
}
```

Полный контракт — в
[`specs/002-daily-ml-emulator/contracts/daily-ml-emulator-api.md`](../specs/002-daily-ml-emulator/contracts/daily-ml-emulator-api.md).
Запущенный эмулятор отдаёт схему сам: `/docs` и `/openapi.json`.

## Как устроено «ранжирование»

Вся «модель» — четыре строки:

```text
N       = число активов во вселенной
offset  = порядковый номер даты (date.toordinal()) mod N
rank(i) = ((i + offset) mod N) + 1
score   = 1 - rank / (N + 1)
```

Циклический сдвиг настроенного списка, величина сдвига — от даты. Правило выбрано так,
чтобы одновременно выполнялись два требования: **одна и та же дата всегда даёт один и
тот же ответ** (в том числе после перезапуска) и **разные даты дают разный порядок**.
Оно зависит только от даты и конфигурации — ни от времени запроса, ни от состояния
процесса, ни от генератора случайных чисел.

## Чего он сознательно не делает

- не воспроизводит логику настоящей модели: ни признаков, ни весов, ни временных окон,
  ни масок;
- не читает рыночные данные и вообще ничего не вычисляет по существу;
- не знает торгового календаря MOEX и отвечает на любую корректную дату, включая
  выходные;
- не проверяет торгуемость актива;
- не хранит историю выданных ранжирований — он без состояния;
- не связан с `backend-api`, `backend-worker`, PostgreSQL и frontend;
- не требует ни секретов, ни базы данных, ни доступа в интернет.

## Когда его нужно убрать

Эмулятор — временный стенд-заместитель, а не реализация контейнера `Daily ML` целевой
архитектуры. Он подлежит удалению целиком (одной директорией плюс сервис в
`docker-compose.yml`), как только к платформе подключается настоящая модель.

Поля `emulated` и `emulation_notice` при этом исчезнут; остальные переживут замену —
разделение зафиксировано в контракте.

## Источник истины о модели

Настоящая модель разрабатывается в отдельном исследовательском репозитории
**`MR-MASTER-DRO`**. Он подключается локально как `Daily ML/` и в Git этого проекта не
входит. Обзорное описание модели — [`docs/daily-ml-model.md`](../docs/daily-ml-model.md).

Из него перенесена форма ответа, а не придумана:

| Что | Где зафиксировано в `MR-MASTER-DRO` |
|---|---|
| Ключ выдачи `decision_date + asset_id` | `pipelines/signal_layer_pre_ig/anchor_score_surface_exporter.py` |
| `asset_id` — экономический актив, `price_series_id` — сшиваемый ценовой ряд | `docs/specs/entity_identity.md` |
| Тикер — маршрутный ключ сырых файлов, а не идентификатор сущности | там же, раздел Core Rule |
| Формат `EQ_AST_<якорь>` / `EQ_PRS_<якорь>` | `pipelines/data_plane_step0/pipeline.py` |
| Значим порядок внутри даты, а не абсолютное значение скора | `docs/specs/pre_ig_signal_extractor_v1.md` |

`fold_id` и `split_role`, входящие в ключ score-поверхности исследовательского
репозитория, в контракт не перенесены: они описывают walk-forward эксперимент, а не
промышленную выдачу.

## Запуск

Подробная инструкция с проверочными сценариями —
[`specs/002-daily-ml-emulator/quickstart.md`](../specs/002-daily-ml-emulator/quickstart.md).

Коротко:

```bash
# в контейнере
docker compose -f deployments/docker-compose/docker-compose.yml up --build daily-ml-emulator

# локально
cd daily-ml-emulator && uv sync
uv run uvicorn daily_ml_emulator.app:app --port 8100
```

## Конфигурация

Секретов среди переменных нет и быть не может.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DAILY_ML_EMULATOR_MODEL_ID` | `daily-ml-emulator-v1` | Значение поля `model_id` в ответе |
| `DAILY_ML_EMULATOR_UNIVERSE_PATH` | `universe/default.json` | Путь к файлу вселенной |
| `LOG_LEVEL` | `INFO` | Уровень логирования |
| `DAILY_ML_EMULATOR_PORT` | `8100` | Порт на хосте (задаётся в compose) |

Путь к вселенной задан относительно рабочего каталога: в образе `WORKDIR` — `/app`,
поэтому он разрешается в `/app/universe/default.json`, а при локальном запуске из
`daily-ml-emulator/` — в `universe/default.json`. Свой список подставляется
монтированием файла поверх, без пересборки образа.

Заведомо непригодная конфигурация — пустая вселенная, дубликаты `asset_id` или
`price_series_id`, пустые поля, более 200 активов — **не даёт контейнеру подняться**:
процесс завершается с ненулевым кодом и сообщением, называющим причину и запись.
Контейнер, отвечающий `500` на каждый запрос, обнаружил бы неисправность позже и дальше
от причины.

## Структура

```text
daily-ml-emulator/
├── Dockerfile                    # multi-stage uv → python:3.12-slim
├── pyproject.toml                # отдельный uv-проект: ruff, mypy, pytest
├── universe/default.json         # вселенная по умолчанию, 10 активов
├── src/daily_ml_emulator/
│   ├── app.py                    # FastAPI: эндпоинты, схемы, обработка ошибок
│   ├── config.py                 # переменные окружения
│   ├── ranking.py                # правило ранжирования — вся «модель»
│   └── universe.py               # загрузка и валидация вселенной
└── tests/
```
