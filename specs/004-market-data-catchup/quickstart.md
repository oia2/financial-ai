# Quickstart: проверка догона пропущенных сессий

Сценарии проверяют фичу на живом стенде. Полная готовность изменения проверяется одной
командой `scripts/check.sh` — этот документ о другом: он показывает, что механизм делает
то, ради чего заведён.

## Предпосылки

```bash
cd deployments/docker-compose
docker compose up -d postgres backend-worker daily-ml-emulator
```

В хранилище должны быть собранные данные хотя бы за несколько сессий: догон отличается от
первичной загрузки по состоянию хранилища, и на пустой базе он намеренно не работает.
Если база пуста — сначала `financial_ai.market_data.cli backfill`.

Команды ниже выполняются внутри контейнера `backend-worker`:

```bash
docker compose exec backend-worker python -m financial_ai.market_data.cli <команда>
```

## С1. Дыра видна

**Что делаем**: удаляем наблюдения за две торговые сессии внутри окна и спрашиваем
состояние.

**Ожидаем**: `gaps` перечисляет ровно эти сессии. Перечень совпадает с разностью «сессии
календаря минус сессии с наблюдениями».

**Покрывает**: FR-001, FR-018, SC-005.

## С2. Неторговые дни пропуском не считаются

**Что делаем**: смотрим `gaps` на окне, включающем выходные и праздники.

**Ожидаем**: в перечне нет ни одного дня, которого нет в календаре.

**Покрывает**: FR-004, SC-003.

## С3. Догон закрывает дыру сам

**Что делаем**: при дыре из С1 запускаем обычный цикл сбора.

**Ожидаем**: за пропущенные сессии появились наблюдения; повторный `gaps` показывает пустой
перечень; вмешательства человека не потребовалось.

**Покрывает**: FR-005, US1, SC-001.

## С4. Даты не переезжают

**Что делаем**: сверяем даты наблюдений, собранных догоном, с датами сессий.

**Ожидаем**: наблюдение за 14 августа сохранено как наблюдение за 14 августа. Переезда на
соседнюю сессию нет ни у одного значения.

**Покрывает**: FR-008, SC-004.

## С5. Повторный догон ничего не меняет

**Что делаем**: запускаем `catchup` дважды подряд при закрытой дыре.

**Ожидаем**: обращений к источникам нет, количество наблюдений не изменилось.

**Покрывает**: FR-009, SC-002.

## С6. Прерывание не теряет собранное

**Что делаем**: останавливаем контейнер посреди догона длинной дыры, затем запускаем снова.

**Ожидаем**: уже закрытые сессии остались закрытыми; догон продолжился с оставшихся, а не
начался заново.

**Покрывает**: FR-010.

## С7. Текущая сессия собирается раньше догона

**Что делаем**: при длинной дыре запускаем цикл и смотрим порядок прогонов по отметкам
времени.

**Ожидаем**: прогон с `trigger = daily` за текущую сессию завершился раньше первого
прогона с `trigger = catchup`.

**Покрывает**: FR-006, SC-008.

## С8. Пустое хранилище — не дыра

**Что делаем**: на чистой базе с собранным календарём запускаем цикл.

**Ожидаем**: обращений за догоном нет, получено сообщение о необходимости первичной
загрузки.

**Покрывает**: FR-014, FR-015, US3, SC-006.

## С9. Диапазонные источники не дорожают с длиной дыры

**Что делаем**: считаем обращения к источникам при дыре в 3 сессии и в 30.

**Ожидаем**: у календаря, ключевой ставки, ЗКЦ и глобальных рядов число обращений
одинаково; растёт только у источников с выборкой по дате.

**Покрывает**: FR-011, SC-007.

## С10. Прогон догона отличим

**Что делаем**: смотрим `stats` за догнанную сессию.

**Ожидаем**: прогон записан с `trigger = catchup`, виден состав источников и исход.

**Покрывает**: FR-017.

## С11. Незакрытое видно

**Что делаем**: имитируем недоступность одного источника за одну сессию и запускаем догон.

**Ожидаем**: остальные источники за ту же сессию собраны; остальные сессии закрыты; в
`gaps` видно, какая сессия и какой источник остались незакрытыми, с причиной.

**Покрывает**: FR-013, FR-019.

## С12. Неполнота доезжает до модели

**Что делаем**: при незакрытой сессии в окне выполняем цикл до запроса ранжирования.

**Ожидаем**: ранжирование получено; в запросе присутствует `dataset.incomplete` с этой
сессией и источником; тот же перечень лежит в манифесте набора.

**Покрывает**: FR-020, FR-021, FR-022, SC-009.

## С13. Полнота входит в дайджест

**Что делаем**: материализуем набор при незакрытой сессии, затем закрываем её и
материализуем снова.

**Ожидаем**: дайджесты различаются, хотя часть рядов совпадает.

**Покрывает**: FR-023, SC-010.

## С14. Состав набора не изменился

**Что делаем**: сверяем файлы набора с описанием из фичи 003.

**Ожидаем**: семейства данных, их окна и раскладка прежние. Добавилось только объявление
полноты.

**Покрывает**: FR-024.

---

## Готовность изменения

```bash
scripts/check.sh
```

Запускать целиком. Частичные прогоны в этом проекте уже пропускали дефекты: `ruff` по
отдельным каталогам не видел `migrations/`, неверный тег базового образа всплывал только
при сборке.
