# Contract: команды просмотра пропусков и догона

Расширение существующего интерфейса `financial_ai.market_data.cli`, введённого фичей 003.
Команды `run`, `calendar`, `backfill`, `verify-cbr` действуют без изменений. У `stats` в
строке прогона добавляется, чем он вызван (`daily`, `catchup`, `backfill`) — иначе прогон
догона за вчерашнюю дату неотличим от обычного.

Интерфейс нужен по FR-018: перечень пропущенных сессий должен быть доступен **без чтения
логов**.

## `gaps` — что пропущено

```
financial_ai.market_data.cli gaps [--asof YYYY-MM-DD]
```

| Параметр | Умолчание | Смысл |
|---|---|---|
| `--asof` | последняя завершённая сессия | Дата решения, от которой отсчитывается окно |

**Вывод при наличии дыры**:

```
окно: 314 торговых сессий, оканчивается 2026-08-28
пропущено сессий: 3

  2026-08-14   нет котировок
  2026-08-15   нет котировок
  2026-08-18   нет котировок

незакрыто по источникам:
  2026-08-20   futures_positions   failed: источник не ответил
```

**Вывод при полном окне**:

```
окно: 314 торговых сессий, оканчивается 2026-08-28
пропущенных сессий нет
```

**Вывод на пустом хранилище**:

```
в хранилище нет наблюдений: нужна первичная загрузка (backfill)
```

**Коды возврата**: `0` — сведения получены, независимо от того, есть дыра или нет; `1` —
не удалось определить (нет календаря, нет доступа к хранилищу).

Отдельный код возврата для «дыра есть» не вводится: команда отвечает на вопрос, а не
выносит вердикт.

## `catchup` — закрыть дыру

```
financial_ai.market_data.cli catchup [--asof YYYY-MM-DD] [--dry-run]
```

| Параметр | Умолчание | Смысл |
|---|---|---|
| `--asof` | последняя завершённая сессия | Дата решения, от которой отсчитывается окно |
| `--dry-run` | выключено | Показать, что было бы собрано, и не обращаться к источникам |

**Поведение**: то же, что у догона в автоматическом цикле. Сессии идут от старых к новым;
каждая пишется прогоном с `trigger = catchup`; недоступность одной сессии не отменяет
остальные.

**Вывод**:

```
догон от 2026-08-14 до 2026-08-18: сессий 3
  2026-08-14  ok       наблюдений 288
  2026-08-15  ok       наблюдений 287
  2026-08-18  failed   equity_d1: источник не ответил
итог: закрыто 2 из 3
```

**Коды возврата**: `0` — все сессии закрыты либо догонять было нечего; `2` — часть сессий
осталась незакрытой; `1` — догон не выполнялся (пустое хранилище, нет календаря).

Код `2` отделён от `1` по той же причине, по которой в фиче 003 отделён сбой ранжирования
от сбоя сбора: «догнали не всё» и «не смогли начать» — разные неисправности с разными
последствиями.

## Что эти команды не делают

- **не запускают первичную загрузку**: на пустом хранилище сообщают о её необходимости и
  завершаются. Первичная загрузка — длинная операция с другим способом обращения к бирже,
  и решение о её запуске принимает человек;
- **не собирают сессии старше окна**: они в набор не попадут;
- **не материализуют набор и не запрашивают ранжирование**: это делает цикл.
