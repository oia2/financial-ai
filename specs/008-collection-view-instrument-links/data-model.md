# Data Model: экран сбора и связи инструментов

Фаза 1. Что добавляется в хранилище и по каким правилам живёт. Денежная точность проекта не
затрагивается: новые величины — даты, коды и счётчики.

Миграция: `0011_instrument_links`.

---

## Новые таблицы

### `market_asset_futures_link` — связь бумаги с семейством контрактов во времени

Отвечает на вопрос «чем и с какой даты запрашиваются позиции по этой бумаге».

| Поле | Тип | Смысл |
|---|---|---|
| `asset_id` | `String(64)` | бумага; часть первичного ключа |
| `contract_code` | `String(32)` | семейство контрактов, которым идёт запрос (`SBRF_F`) |
| `valid_from` | `Date` | дата, с которой связь подтверждена источником; часть ключа |
| `valid_till` | `Date, null` | последняя дата действия; `null` — связь действует |
| `chosen_by` | `String(32)` | основание выбора: `underlying_id`, `ticker_match` |
| `open_interest` | `Integer, null` | открытый интерес на момент выбора, если кандидатов было несколько |
| `recorded_at` | `DateTime(tz)` | когда запись сделана |

Правила:

- у бумаги в один день **не более одной действующей связи**; открытие новой закрывает
  прежнюю датой предыдущего дня;
- интервалы одной бумаги не пересекаются;
- запись появляется только тогда, когда источник подтвердил связь. Отсутствие наблюдений
  за более ранние даты связь назад не продлевает и не запрещает (R4).

### `market_asset_alias` — имена бумаги во времени

Отвечает на вопрос «этот тикер — новая бумага или прежняя под новым именем».

| Поле | Тип | Смысл |
|---|---|---|
| `ticker` | `String(32)` | тикер; часть первичного ключа |
| `valid_from` | `Date` | с какой даты тикер принадлежит сущности; часть ключа |
| `asset_id` | `String(64)` | сущность |
| `valid_till` | `Date, null` | последняя дата действия имени |

Правила:

- появление тикера, чей ISIN уже известен системе, — переименование: новые наблюдения
  относятся к прежней сущности, прежний тикер закрывается датой;
- если ISIN у бумаги отсутствует, якорем остаётся тикер — законная форма, принятая и в
  исследовательском репозитории.

### `market_session_skip` — пропущенные сессии и причины

Отвечает на вопрос «почему этой сессии нет в собранном».

| Поле | Тип | Смысл |
|---|---|---|
| `session_date` | `Date` | сессия; часть первичного ключа |
| `decided_at` | `DateTime(tz)` | когда решение принято; часть ключа |
| `reason` | `String(32)` | `withheld_until_close`, `retry_delay`, `attempts_exhausted`, `gap_over_limit` |
| `run_id` | `String(36), null` | прогон, в котором решение принято |
| `detail` | `Text, null` | уточнение для человека: когда следующая попытка, сколько попыток израсходовано |

Правила:

- перечень причин закрытый (FR-002); новая причина добавляется вместе с местом, где она
  принимается;
- запись переживает перезапуск сборщика — в этом и смысл таблицы: ход работы живёт в
  памяти процесса намеренно, а причины пропусков обязаны жить дольше.

## Изменения существующих таблиц

### `market_asset`

| Поле | Тип | Смысл |
|---|---|---|
| `isin` | `String(12), null` | устойчивый идентификатор сущности; `null`, если источник его не отдаёт |

### `market_futures_position`

| Поле | Тип | Смысл |
|---|---|---|
| `contract_code` | `String(32)` | семейство контрактов, которым собрано наблюдение; **входит в первичный ключ** |

Ключ становится `asset_id + session_date + contract_code`. Повторный сбор той же даты
другим контрактом не замещает прежнее наблюдение молча (FR-030, FR-039). Существующие
строки получают код действующей связи, а где её нет — значение `unknown`, чтобы отличить
старое наблюдение от собранного по новым правилам.

### `market_ingest_run`

| Поле | Тип | Смысл |
|---|---|---|
| `period_from` | `Date, null` | начало периода, который покрывает исход |
| `period_till` | `Date, null` | конец периода; для посессионного источника равен `session_date` |
| `coverage_version` | `Integer, null` | версия правила полноты, которым исход проверен |
| `coverage_reason` | `String(64), null` | исход успешной проверки: `completed_with_values` или `completed_no_new_rows` |

Без периода источники, забирающие данные за диапазон одним запросом, выглядят несобравшими
всё, кроме последней сессии (R5).

`coverage_version` отличает успех, проверенный действующим правилом полноты, от успеха,
записанного прежним «любая строка закрывает день» (FR-032c). `NULL` означает
«правилом не проверен»: миграция старым записям версию **не присваивает**, наблюдения и
журнал сохраняются целиком. Версия ставится только после успешной проверки результата.
Нулевое число новых строк само по себе полноту не доказывает: `coverage_reason` хранит,
что завершившийся по текущему правилу сбор не добавил новых строк; ошибки разбора и
незавершённые источники не получают ни эту причину, ни версию.

Одно целое число вместо отдельной таблицы: различать нужно ровно две вещи — проверено или
нет, — а версий правила за всё время будет единицы.

### `market_coverage_boundary`

Однократная граница перехода на новое правило полноты для существующей базы (FR-032c).

| Поле | Тип | Смысл |
|---|---|---|
| `coverage_version` | `Integer, PK` | версия правила, для которой зафиксирована граница |
| `boundary_session` | `Date, null` | последняя закрытая сессия на момент включения правила |
| `recorded_at` | `DateTime(tz)` | когда граница зафиксирована |

Строка пишется один раз и при перезапуске **не пересчитывается**: иначе каждый запуск
сдвигал бы границу вперёд и старая область исчезала бы сама собой. Всё, что не позже
границы, относится к старой области и в автоматический исторический добор не берётся —
включая применимые пары без исходов и без наблюдений. Пустая база границы не получает: там
нет старого покрытия, и первичная загрузка остаётся отдельным режимом.

## Правила расчёта

**Полнота группы за сессию** (одно правило на сводку, поиск пропусков и готовность
ранжирования):

> Сессия группы закрыта, когда по каждому источнику группы **вся применимая работа этого
> источника за сессию обработана**: получены значения либо установлено подтверждённое
> отсутствие или неприменимость с основанием, и последний по порядку исход источника,
> период которого включает сессию, — успешный и проверен действующей версией правила.

Наличие любой непустой строки закрытием не является: у источника из многих независимых
частей одна часть ничего не говорит про остальные (FR-032). Ошибка, остановка и
незавершённый прогон за частичными наблюдениями не скрываются. Сессии со старым успехом
без `coverage_version` обозначаются как `requires_audit`: они не считаются ни собранными,
ни работой автоматического добора (FR-032c).

Диапазонный исход закрывает только подтверждённые границы периода; неопределённая дата
внутри диапазона оставляет весь период незавершённым (FR-032d).

**Знаменатель числа бумаг**: бумаги, у которых есть котировка за дату сводки, причём сессия
этой даты собрана успешно (R11).

**Число бумаг с фьючерсом**: бумаги знаменателя, у которых на дату сводки есть действующая
связь.

**Применимость позиций**: позиции запрашиваются только по бумагам знаменателя с действующей
связью и только за даты внутри интервала связи (FR-017, FR-020d).

## Объявление календаря

Календарь перестаёт быть только таблицей дат: рядом с ним появляется **объявление**,
перенесённое из исследовательского репозитория (`configs/calendars/moex_daily.yaml`), —
идентификатор календаря, рынок и доска, опорная бумага, часовой пояс и правила даты
решения: снимок на `t` собирается после закрытия сессии `t`, исполнение на открытии `t+1`,
исполнение в тот же день запрещено, лаг по умолчанию одна сессия.

Объявление лежит в коде рядом с календарём и читается человеком без чтения сборщика
(FR-042). Хранение самих дат остаётся в `market_trading_session` — это разница реализации,
а не правил.

Из объявления следует порядок прогона: календарь обновляется первым, остальные источники
собираются **не дальше его последней даты** (FR-043). Так устроен и оркестратор
исследования, где источники синхронизируются «до последней даты календаря».

## Что не добавляется

- **Статус листинга** (`A`/`N`/`S`) и его история — решение владельца 2026-09-17.
- **Срочные серии контрактов** — единицей связи выбрано семейство (R2).
- **Миграция наблюдений на ISIN** — наблюдения продолжают ключеваться существующими
  идентификаторами (FR-018).
- **Таблица под журнал прогонов** — журнал уже есть в `market_ingest_run`, итог получается
  свёрткой по `run_id` (R9).
