## T204. Разбор ISS: float убран с пути значения

**Причина.** `_get_json()` возвращал `response.json()`, а он разбирает дробные числа JSON
в `float`. Перевод в `Decimal` у потребителя потерю не возвращает: к этому моменту
восстанавливать уже нечего.

**Правка.** Одна точка перевода — `iss/client.py:_loads()`:
`json.loads(body, parse_float=Decimal)`. `to_decimal()` пропускает `Decimal` как есть и
предупреждает, если значение всё-таки пришло как `float`, — тогда потеря произошла до
разбора, и место видно по логу.

**Почему дефект не ловился.** Все тесты `test_precision.py` подавали значения **строками**,
а на строках потери нет никогда. HTTP-путь не проходил ни один из них: ISS отдаёт числа
JSON без кавычек.

**Доказательство.** Четыре новые регрессии в `backend/tests/market_data/test_precision.py`
проходят ответ биржи целиком — байты HTTP → разбор → домен:

| Проверка | До правки | После |
|---|---|---|
| `123456789.123456789` в ответе | `123456789.12345679` | `123456789.123456789` |
| тип дробного значения | `float` | `Decimal` |
| `1e-9` | `1.0000000000000001e-09` (float) | `Decimal("1E-9")` |
| `null` | — | остаётся `None`, нулём не становится |
| `0` | — | `0`, отличается от `None` |

Три из четырёх падают на прежнем коде (проверено подменой `_loads` обратно на
`response.json()`), четвёртая — сторожевая на `null`/`0`.

Потребители ответа проверены: котировки, агрегаты, глобальные ряды, Brent, справочники,
открытый интерес и размер лота. Целые числа `json` разбирает в `int` и без правки,
`int(Decimal)` в открытом интересе и лоте работает без изменений.

Прогон `tests/market_data/` целиком на живой PostgreSQL: **409 passed**.


## T205. Частичный сбор перестал быть успехом

**Причина.** `_fetch_series()` возвращал `{}` и при ошибке транспорта, и при корректном
пустом ответе. Обход рядов шёл дальше, итог складывался из уцелевших, и источник
записывался `ok`. Один полученный ряд из пяти закрывал сессию всем пяти.

У ЦБ причина зеркальная: ошибка кривой поднималась выше и уносила весь источник вместе с
уже полученной ставкой — отсюда 311 значений `CBR_KEY_RATE` против 308 у каждой точки
`CBR_ZCYC_*` на стенде.

**Правка.**

- `SeriesFetchError` отделяет несостоявшееся обращение от корректного пустого ответа.
  Пустой словарь теперь означает ровно одно: биржа ответила, значений нет.
- `SourcePartialError` (в `interrupt.py`, рядом с `SourceStoppedError`) — исход
  «полученное записано, применимая работа сделана не вся». Несёт фактическое
  `rows_written` и перечень незавершённого словами.
- `run_source()` записывает его как `failed` с фактическим числом строк: полученное
  остаётся в хранилище, но сессию по источнику не закрывает.
- `_sync_cbr_range()` собирает ставку и кривую независимо: падение любой из них не
  отменяет другую, полученное сохраняется, незавершённое называется в исходе.
- Счётчик подряд идущих неудач видит эти исходы без правок:
  `health.record(source_id, outcome.status != STATUS_FAILED)`.

**Доказательство.** `backend/tests/market_data/test_partial_sources.py`, 8 проверок —
ровно сценарии приёмки T205:

| Сценарий | Ожидание | Результат |
|---|---|---|
| 1 успешный ряд + 4 ошибки | ряд сохранён, источник незавершён | `rows_written=1`, `unfinished=(RTSI, RGBI, RVI, USD_ISS)` |
| все ряды упали | неуспех, сохранять нечего | `rows_written=0`, записи не было |
| все ряды собраны | источник закрыт | исключения нет, `written=5` |
| корректный пустой ответ | не неуспех | `written=0`, записи не было |
| остановка посреди обхода | отдельный исход | `SourceStoppedError(rows_written=1)` |
| ставка + ошибка кривой | ставка сохранена, кривая — работа | `rows_written=1`, кривая в `unfinished` |
| ошибка ставки + кривая | кривая сохранена | `rows_written=1`, ставка в `unfinished` |
| обе части собраны | источник закрыт | `written=2` |

Прогон `tests/market_data/` целиком: **417 passed** (было 409 до добавления этих восьми).
