# Quickstart: как убедиться, что фича работает

Сценарии проверки готовой работы. Не инструкция по реализации: код живёт в задачах.

## Предварительно

```bash
cd deployments/docker-compose
docker compose up -d
```

Гейт готовности — одной командой из корня репозитория:

```bash
scripts/check.sh
```

Частичные прогоны гейтом не являются.

---

## 1. Сбор не зависит от настроек модели

Исходная жалоба: «автосбор собирает только котировки».

```bash
# оставить в обязательных группах модели одни котировки
sed -i 's/^DAILY_ML_REQUIRED_DATA_GROUPS=.*/DAILY_ML_REQUIRED_DATA_GROUPS=["quotes"]/' \
  deployments/docker-compose/.env
docker compose up -d backend-worker
```

Удалить наблюдения позиций за одну собранную сессию и дождаться ближайшего прогона.

**Ожидается**: сессия снова попадает в работу, позиции добираются. Раздел показывает
пропуск и причину, если добрать не удалось.
**Провал**: день считается собранным, потому что котировки на месте.

---

## 2. Сегодняшняя сессия собирается в тот же вечер

```bash
docker compose logs backend-worker | grep -i "календар"
```

**Ожидается**: после времени порога календарь запрошен повторно, сегодняшняя дата в нём
появилась, сессия собрана в тот же вечер.
**Провал**: календарь опрошен только на первом тике суток, сегодняшняя сессия собирается
следующей ночью.

---

## 3. Причины пропусков доживают до экрана

Оборвать источник на одной сессии (например, подменив адрес) и дождаться, когда сессия
уйдёт в выдержку.

**Ожидается**: в разделе «Рыночные данные» пропуск назван с причиной и сроком следующей
попытки; после перезапуска `backend-worker` причина на месте.
**Провал**: причина только в логах.

---

## 4. Итог прогона и журнал переживают перезапуск

```bash
docker compose restart backend-worker
```

**Ожидается**: после перезапуска раздел показывает итог последнего прогона и журнал
последних прогонов; прогон, оборванный перезапуском, помечен прерванным.
**Провал**: панель пуста или прогон навсегда «идёт».

---

## 5. Связь бумаги и фьючерса живёт во времени

```bash
docker compose exec postgres psql -U financial_ai -d financial_ai \
  -c "select asset_id, contract_code, valid_from, valid_till, chosen_by
        from market_asset_futures_link order by asset_id limit 10;"
```

**Ожидается**: у бумаг есть действующие интервалы с основанием выбора; смена контракта
закрывает прежний интервал и открывает новый.
**Провал**: таблица пуста или у бумаги несколько действующих интервалов сразу.

Пройдено на стенде 2026-09-18: 67 связей, все подтверждены эмитентом, у каждой бумаги ровно
один действующий интервал. Связь `ABIO → ISKJ_F` правилом из названий не выводится — её даёт
только базовый актив из списка серий.

---

## 6. Позиции помнят контракт

```bash
docker compose exec postgres psql -U financial_ai -d financial_ai \
  -c "select asset_id, session_date, contract_code from market_futures_position
        order by session_date desc limit 5;"
```

**Ожидается**: у каждого наблюдения есть код контракта; повторный сбор той же даты другим
контрактом добавляет запись, а не замещает прежнюю.

---

## 7. Крайние случаи состава инструментов

```bash
cd backend && python -m pytest tests/integration -k instruments -v
```

Семь испытаний на подготовленных ответах источника: появилась бумага; появился фьючерс;
сменилось семейство контрактов; бумага переименована; бумага перестала торговаться; у
бумаги несколько контрактов; соответствие потеряно.

**Ожидается**: каждое проходит, прогон не прерывается, ряды не смешиваются, изменение
видно в отчёте.

## 8. Раздел соответствует макету

```bash
node "<путь к проекту Open Design>/design-assets/market-data-collection-v4/verify.cjs"
node "<путь к проекту Open Design>/design-assets/market-data-collection-v4/check-width.cjs"
```

**Ожидается**: обе проверки зелёные, а раздел в браузере совпадает с артефактом
`market-data.html` при сопоставлении состояний из
[contracts/ui-states.md](./contracts/ui-states.md).

---

## 9. Открытие раздела ничего не запрашивает у биржи

Открыть раздел и посмотреть журнал worker.

**Ожидается**: обращений к внешним источникам нет — числа сводки посчитаны по хранилищу.
**Провал**: каждое открытие раздела стоит запросов к бирже.
