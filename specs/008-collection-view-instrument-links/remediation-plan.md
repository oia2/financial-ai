## Задание исполнителю

рыночных данных. Выполнять T203–T214 последовательно. Для каждого шага ниже указаны
файлы, действия и критерий приёмки. Не отмечать шаг выполненным по одному наличию кода.

Работа закончена, когда сводка, план сбора, готовность Daily ML и объявление полноты набора
согласуются на одинаковой дате и конфигурации; сбои не превращаются в доказательство
отсутствия данных; уже полученные значения переживают остановку; подтверждённые дыры в БД

из обязательного входа проблемные группы; искусственные нули; сокращённые окна; увеличение
числа повторов вместо устранения причины; ускорение за счёт обрезания ответа источника.

## Термины и целевое правило

**Работа источника за дату** — обработка всего применимого входа этого источника на эту
дату: например, всех запрошенных глобальных рядов или всех применимых пар
«актив — семейство фьючерса». Одна строка не доказывает выполнение всей работы.

**Подтверждённое отсутствие** — корректный ответ на корректный запрос, разобранный по
проверенному контракту источника, который явно позволяет заключить, что данных нет.
Отсутствующая HTML-таблица, неожиданный JSON-блок, таймаут, чужая дата ответа и отсутствие
значений в редких пробах сами по себе таким подтверждением не являются.

**Неприменимость** — источник не требуется для данной пары или даты по подтверждённым
правилам: например, у бумаги нет фьючерса или дата лежит вне окна выбранной группы.
Недоступность и непубликация задержанного значения неприменимостью не являются.

| Ситуация | Сохранять полученное | Источник закрыт | Поведение повторного сбора |
|---|---|---|---|
| Всё применимое обработано, получены значения | Да | Да | Пропустить |
| Есть доказанное отсутствие/неприменимость с причиной | Да, если есть | Только подтверждённая область | Пропустить эту область |
| Часть получена, часть упала или осталась неизвестной | Да | Нет | Добрать незавершённое |
| Остановка или обрыв процесса | Да, уже сохранённое | Нет | Продолжить незавершённое |
| Все запросы упали | Нечего сохранять | Нет | Ограниченные повторы с видимой причиной |
| Старый `ok` с нулём строк без доказательства | Не удалять историю | Не считать достаточным доказательством | Аудит и адресный ремонт |

Не требовать ненулевого значения в каждой ячейке: законные пропуски и `NULL` остаются.
Не требовать позиций от бумаг без фьючерса. Не считать строку, заполненную хотя бы одним
полем, доказательством полноты всего источника.

## T205. Сохранять частичные глобальные данные и сообщать об ошибках

**Файлы:** `sources/global_series.py`, `sources/cbr.py`, `ingest.py`, тесты источников.

1. `_fetch_series()` не должен возвращать `{}` при ошибке транспорта/разбора.
2. Обход независимых рядов может продолжаться после сбоя; успешно полученные значения
   сохраняются. Итог сообщает неуспех, конкретные несобранные ряды и число сохранённых строк.
3. Для ЦБ сохранить ставку, если получение кривой упало, но не закрывать весь источник.
4. Различать корректный пустой ответ и сломанный контракт. Не обозначать неизвестность
   словами «данных нет». Не записывать успех при полном отсутствии значений без основания.

**Приёмка:** 1 успешный ряд + 4 ошибки → сохранён 1 ряд, источник незавершён;
все ошибки → неуспех; ставка + ошибка кривой → ставка сохранена, кривая остаётся работой.
Счётчик последовательных неудач видит эти ошибки.

## T206. Исправить поиск истории фьючерса

**Файлы:** `sources/positions_client.py`, `sources/positions.py`,
`backend/tests/market_data/test_positions_source.py`.

1. `_has_data()` должен передавать сетевую ошибку вызывающему. Остановка должна иметь
   отдельный исход `SourceStoppedError`, включая отмену повторов внутри `_post()`.
2. Не кешировать «истории нет», если хотя бы одна необходимая проба не завершилась.
   Редкая сетка отрицательных проб не доказывает отсутствие данных между пробами.
3. Успешный снимок, полученный при поиске, повторно использовать для сбора той же пары
   «контракт — дата». Ограничить кеш временем одного прогона и числом действительно
   полученных снимков; не создавать неограниченное долговременное хранилище HTTP-ответов.
4. Первое **собранное** наблюдение не считать датой появления контракта. Если нижняя
   граница существования не доказана, оставить её неизвестной и проверять нужные даты.

**Приёмка:** сбои всех проб не дают `ok`; сбой ранней пробы не отсекает раннюю историю;
данные между пустыми пробами не теряются; найденный снимок не запрашивается второй раз;
остановка прекращает новые обращения и повторы.

## T207. Сохранять позиции до выхода по ошибке или остановке

**Файлы:** `sources/positions.py`, `repository.py`, `ingest.py`, тесты остановки/продолжения.

1. Сохранять полученные позиции ограниченными пачками и при выходе по ошибке/остановке.
   Проверить границы **commit**, а не только вызов `upsert`: обрыв процесса после записи
   незакоммиченной пачки не должен уничтожать все предыдущие пачки.
2. При ошибке HTTP после нескольких успешных контрактов сохранить предыдущие значения и
   записать неуспех с фактическим `rows_written`. При остановке — `stopped`.
3. Проверять наличие собранного по ключу `asset_id + contract_code + session_date`.
   Чужое семейство и его первая дата не доказывают наличие данных текущего семейства.
4. Частичные непустые строки не перезаписывать пустыми ответами; неизвестные поля не
   подменять нулями. Повтор должен запрашивать только недостающую работу.

**Приёмка:** первый контракт успешен, второй упал → первый остаётся в БД;
после остановки и после перезапуска продолжение его не спрашивает; смена семейства не
скрывает недобор и не затирает прежний контракт.

## T208. Сделать одно доказуемое правило полноты

**Файлы:** `completeness.py`, `repository.py`, `groups.py`, `models.py`, `ingest.py`;
при изменении схемы — новая Alembic-миграция, старые миграции не переписывать.

1. Закрытие определять по полностью обработанной применимой работе, а не по наличию
   любой строки. Ошибка/остановка/незавершённый прогон не должны скрываться за частичными
   наблюдениями. Успех после добора снимает прежнюю незавершённость.
2. Учитывать период исхода для каждой входящей в него торговой сессии и общий порядок
   исходов. При продолжении с тем же `run_id` новое завершение должно учитываться правильно.
3. Отличать старый успех от успеха, проверенного новым правилом. Предпочтительный простой
   вариант — nullable `coverage_version` у `IngestRun` и одна константа версии правила.
   Новая версия ставится только после успешной проверки результата. Старым записям
   миграция не присваивает её автоматически; наблюдения и журнал сохраняются.
   Непроверенное старое покрытие обозначать как `requires_audit` в результате расчёта
   полноты и исключать из **автоматического исторического** добора до явного запуска
   ремонта. Для существующей БД сохранить однократную границу перехода — последнюю
   закрытую сессию на момент включения нового правила; при перезапуске её не пересчитывать.
   В старую область входят все применимые пары до этой границы, в том числе без исходов
   и наблюдений. Частичный ремонт с новым `failed`/`stopped` не выводит остаток из этой
   области. Команда ремонта разрешает только свой диапазон и источники, а не снимает
   ограничение глобально. Новые даты после границы собираются обычным путём; пустая БД
   сохраняет отдельный режим первичной загрузки. `requires_audit` не означает готовность
   обязательного входа. Записать это правило и способ хранения границы в T203.
4. Закрывать диапазон только в подтверждённых границах. Если в диапазоне есть неопределённые
   даты, нельзя объявить успешным весь период; сохранять подтверждённые участки либо
   оставить диапазон незавершённым, повторно используя уже полученные данные.
5. Обработать первичную загрузку: история одной бумаги не подтверждает полноту всей доски.
   Не оставить `backfill.py` обходным путём старого правила «любая строка закрывает день».
6. Для пустого успеха хранить проверяемую причину. Простой `rows_written=0` не доказывает
   отсутствие данных: это также бывает при ошибке разбора и при пропуске готовой работы.
7. Определить состав применимой работы и минимальную область доказательства для каждого
   источника: ряд/дата, актив/семейство/дата либо полный ответ доски с проверенной
   пагинацией. `coverage_version` у исхода недостаточно для частично выполненной работы:
   подтверждённое отсутствие в завершённой части хранить с областью и основанием так,
   чтобы оно переживало перезапуск. Неизвестное и задержанная публикация остаются
   незавершёнными; по ним нельзя сохранить окончательное отсутствие.

**Приёмка:** все строки таблицы состояний выполняются для сессионных и диапазонных
источников, включая частично пересекающиеся периоды, остановку и успешное продолжение.
Старые данные без подтверждения честно обозначаются как требующие аудита, а не удаляются.
Первый тик после миграции и следующий перезапуск не начинают сбор старого окна:
проверить старый пустой исход, отсутствие исхода и частично выполненный ремонт.
Новая закрытая сессия собирается. Явная команда ремонта разрешает только указанную
область. Если одна пара подтверждённо пуста, а вторая завершилась таймаутом, после
перезапуска повторяется только вторая.

## T210. Ограничить работу выбором групп и окнами

**Файлы:** `runner.py`, `ingest.py`, `completeness.py`, `advance.py`, тесты догона.

Строить план как пары «источник — дата». Для ручного запуска брать только выбранные
группы, их окна и заданный диапазон; для автоматического — все собираемые группы с их
окнами. Перечень обязательных групп ML не использовать для выбора работы сборщика.
Окно вычислять от даты плана, сохранять при продолжении, не сдвигать от очередной старой
сессии. В момент исполнения повторно исключать уже закрытые пары.

Пары описывают логическую работу, а HTTP-запросы планируются с учётом диапазонного
интерфейса источника. Разрешить одному диапазонному ответу содержать уже известные
внутренние даты, если это уменьшает обращения за разреженными пропусками; закрепить
это уточнение в T203. Полностью готовый диапазон не запрашивать. Для позиций, где запрос
адресован одной паре, повтор готовой пары не допускается. Число логических пар не равно
числу HTTP-попыток.

**Приёмка:** при окне котировок 314 и позиций 82 нет обращений за позициями вне 82 сессий;
выбор только позиций не включает старые дыры агрегатов; полностью собранная выбранная
группа не запускает пустой прогон; все группы собирают свои недостающие даты; продолжение
сохраняет режим, окна, порядок и счётчики. Разреженные пропуски диапазонного источника
не превращаются в отдельный запрос на каждую дату без причины.

## T211. Устранить лишние обращения и измерить результат

**Файлы:** `sources/brent.py`, `sources/trading_calendar.py`, `iss/client.py`,
`sources/positions_client.py`, `coverage.py`, `repository.py`.

1. Добавить измерение фактических HTTP-попыток по источникам: успешные ответы, повторы,
   поисковые пробы и время. Номер инструмента не называть числом запросов.
2. Brent: проверить на живом ISS получение истории нужных контрактов диапазонами, включая
   истёкшие контракты. Использовать исторически полный состав; текущий список торгуемых
   контрактов не заменяет его. Сохранить действующее правило выбора фронтального контракта.
   Убрать обход всего срочного рынка на каждую дату там, где диапазонная выборка подтверждена.
   Сравнить значения старого и нового путей до переключения. Если источник не позволяет
   оптимизацию, зафиксировать ответ и измеренную цену корректного fallback; не угадывать URL.
3. Календарь: первичная загрузка получает историю целиком, дальнейшее обновление — нужный
   хвост с обоснованным перекрытием, сохраняя суточный гейт и дозагрузку новых сессий.
4. Сводка: повторить замер на одной БД, устранить повторные чтения и обработку всего
   журнала в Python там, где SQL может сразу дать нужный результат. Общие результаты
   использовать в пределах одного запроса; не добавлять кеш без правил инвалидирования.
5. Не ускорять позиции общим параллельным использованием состояния формы: `VIEWSTATE`
   изменяется ответами. Сначала убрать повторы, лишние даты и потерю результатов.
6. Сохранить повторы с ограничением, настраиваемый темп и правильную пагинацию. При
   увеличении `limit` проверить реальный размер страницы/курсор, а не предполагать, что
   сервер вернул запрошенное число строк.

**Приёмка:** таблица «до/после» на одинаковых датах с HTTP-попытками, SQL-запросами,
строками и временем; повтор готовой работы — 0 внешних запросов за её данными;
одна найденная пара позиций не спрашивается повторно. Brent даёт те же значения на
историческом диапазоне, включая перекат и истёкшие контракты. Либо число обращений
измеренно снижено, либо ограничение источника доказано конкретными ответами и сохранён
корректный fallback с измеренной стоимостью. Во втором случае оптимизацию Brent явно
отметить как недостигнутую, а не заявлять ускорение.

## T212. Восстановить накопленные данные управляемой операцией

оставшиеся пропуски объяснены и не скрыты; сводка, план и набор совпадают; ремонт не
переспрашивает собранные пары и не запускается сам после перезапуска. Ошибки, повторы
