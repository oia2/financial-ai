# Contract: сводка полноты

Сводка отвечает на вопрос «что у нас есть» и считается **по хранилищу**. Открытие раздела
не порождает обращений к внешним источникам (FR-011): иначе каждый заход человека стоил бы
двух запросов к бирже ради подписи под таблицей.

---

## `GET /api/market-data/coverage?asof=YYYY-MM-DD`

```json
{
  "asof_date": "2026-09-16",
  "catchup_window": { "date_from": "2025-06-10", "date_till": "2026-09-16", "sessions": 314 },
  "universe": {
    "assets": 243,
    "assets_with_futures": 63
  },
  "groups": [
    {
      "group": "global",
      "title": "глобальные ряды",
      "has_history": true,
      "window_sessions": 314,
      "sessions_covered": 311,
      "coverage_ratio": 0.9904,
      "gaps": 3,
      "requires_audit": 0,
      "period_from": "2025-06-10",
      "period_till": "2026-09-16",
      "rows_total": 2826,
      "rows_with_values": 2826,
      "value_ratio": 1.0,
      "looks_collected_but_empty": false,
      "sources": [
        { "source_id": "global_series", "title": "Глобальные ряды ISS", "scope": "period", "status": "ok", "sessions_covered": 314 },
        { "source_id": "cbr", "title": "Курсы и ставка ЦБ", "scope": "period", "status": "ok", "sessions_covered": 314 },
        { "source_id": "brent", "title": "Brent", "scope": "session", "status": "failed", "sessions_covered": 298, "reason": "источник не ответил вовремя" },
        { "source_id": "index_constituents", "title": "Состав индекса", "scope": "session", "status": "ok", "sessions_covered": 314 }
      ]
    }
  ]
}
```

**Что добавляет эта фича:**

- `universe.asof_date` — сессия, по которой посчитан состав: последняя, за которую котировки
  собраны. Может быть старше даты сводки, и молчать об этом нельзя. `null` означает, что
  собранных сессий в пределах окна нет вовсе. Признак торгуемости выводится из наблюдений,
  поэтому на несобранной дате состав вышел бы нулевым и несобранная сессия выглядела бы
  отсутствием торгов (FR-019a).
- `next_session` — сессия, которую возьмёт следующий сбор: свежая дата сводки идёт первой,
  остальные недостающие — по возрастанию (FR-045). Выдержка
  после неудачи и предел попыток учитываются тем же правилом, каким их учитывает сам сбор.
  Когда несобранного нет, поле равно `null`: возьмут СЛЕДУЮЩУЮ сессию, а её календарь не
  знает — он строится по состоявшимся торгам, и называть последнюю собранную значило бы
  обещать собрать уже собранное. Когда несобранное есть, но взять нельзя ни одну сессию,
  поле тоже `null` — и этот случай отличается признаком `next_session_blocked`
  (FR-024a, FR-054).
- `next_expected_session` — ожидаемая дата новой сессии независимо от повторов прошлых.
  Вычисляется сборщиком: первый будний день не раньше московского сегодня и строго после
  даты сводки. Утром понедельника при пятничной сводке это понедельник, даже если пятница
  требует повтора. Повтор называется отдельно полем `next_session`.
  Это ориентир до подтверждения календарём биржи, без гарантии праздников и внеочередных
  торгов. Обе подписи интерфейса используют это поле и называют дату ожидаемой.
- `next_session_closed` — названная сессия уже закрыта: ждать её закрытия нечего, сбор
  возьмёт её ближайшим прогоном. При отставании это обычное дело, а подпись «после закрытия
  сессии» у даты трёхмесячной давности читается как обещание, которого никто не давал
  (FR-054). Сравнивается с текущим московским временем и настроенным порогом сбора,
  а не с последней известной датой календаря.
- `next_session_blocked` — у всех недобранных сессий исчерпаны попытки. `true` требует
  ручного запуска **прошлых** сессий, но не запрещает сбор новых по расписанию и не
  скрывает `next_expected_session` (FR-054).
- `universe.assets` — бумаги, у которых есть котировка за дату сводки в успешно собранной
  сессии (FR-013, FR-037). Не «все бумаги, когда-либо встречавшиеся в данных»: такой
  знаменатель только растёт и медленно врёт.
- `universe.assets_with_futures` — из них те, у кого на дату сводки действует связь с
  семейством контрактов (FR-010).
- `groups[].state` и `groups[].sources[].state` (с 2026-09-23, FR-024e) — состояние из
  закрытого перечня, выбранное сервером по старшинству: `empty` (только у группы:
  подтверждено, но значений < 1 %), `running` (идёт обращение за недоказанную сессию),
  `source_error`, `internal_error`, `interrupted` (последняя причина `stopped` или
  `interrupted`), `missing` (недоказанные сессии без записанной причины, включая
  непроверенную старую историю), `complete`. Интерфейс только подписывает состояние.
- `groups[].group` (с 2026-09-24, FR-060a) — `quotes`, `aggregates`, `fund_quotes`,
  `fund_aggregates`, `global`, `positions`, `reference`. `quotes` и `aggregates` — строки
  акций, `fund_*` — строки фондов тех же источников (`equity_d1`, `equity_agg`); исходы
  источника у пары групп общие. Окно `fund_*` начинается 22.06.2026 (FR-060b).
- `groups[].model_input` (с 2026-09-24, FR-060c) — идут ли строки группы во вход модели.
  `false` у групп фондов; интерфейс подписывает группу «пока не входит в модель».
- `universe.assets` (уточнено 2026-09-24, FR-060e) — считаются только акции.
- `groups[].latest_failure` — последняя по дате причина незавершённой работы группы:
  `session_date` (у справочника `null`), `reason`, `kind`, `title` источника; `null`, если
  причин нет.
- `groups[].sources[].status` — прежнее поле для старых читателей: `ok` при `complete`,
  `failed` только при `source_error`/`internal_error`, иначе `partial`. Остановка,
  перезапуск и идущее обращение `failed` не дают (FR-033f). Прежнее описание: `ok` (окно покрыто целиком), `partial` (покрыто не целиком, но
  источник не падал) или `failed` (были записанные неудачи, они названы в `failures`). Три
  состояния, а не два: пока их было два, экран называл ошибкой всякую неполноту и не мог
  показать причину, потому что причины не было.

  `ok` означает, что **вся применимая работа источника в окне обработана** (FR-032), а не
  что на каждую сессию нашлась строка или пустой успешный исход. Пока значило второе,
  сводка показывала Brent полным — 314 из 314 — при 122 отсутствующих датах в том же окне
  (стенд 2026-09-20).
- `groups[].requires_audit` — число сессий окна, где хотя бы один обязательный источник
  требует аудита старого покрытия. `groups[].sources[].requires_audit` — число сессий окна, закрытых прежним правилом и
  действующим не проверенных (FR-032c). Такие сессии не считаются ни собранными, ни
  работой автоматического добора: они ждут явной команды ремонта. Поле необязательное;
  `0` и его отсутствие читаются одинаково.
- Для посессионных и диапазонных источников `requires_audit` включает исходы версии 1:
  эта версия могла быть поставлена без проверки контракта ответа. Полноту подтверждает
  только версия 2 вместе с доказательствами всех применимых единиц. Миграция не переводит
  старые исходы автоматически и не запускает ремонт.
- `groups[].sources[].failures_total` — сколько неудач всего; список ограничен двадцатью.
- `groups[].sources[].failures` — неудачи источника по дням: `session_date`, `reason` и `kind`
  (FR-033f; `unpublished` — ожидание публикации, FR-032h, FR-032i, состояние
  источника при нём — `missing`, а не `source_error`), только за недоказанные сессии, свежие сверху, не более двадцати. Идущее
  обращение (`running`) неудачей не является и в перечень не входит. Берётся ПОСЛЕДНИЙ прогон каждой пары «сессия — источник» и только
  неуспешный: удачный повтор снимает отметку, иначе перечень стал бы журналом былых неудач.
  «Ошибка источника» без дня и причины — состояние, с которым человеку нечего делать.
- `groups[].sources` — исход по **каждому** источнику группы. Полнота группы считается по
  каждому источнику, а не по любому: успех одного не закрывает пропуск другого (FR-032).
- `sources[].scope` — `session` или `period`. Источник с выборкой за период закрывает все
  сессии своего периода одним исходом (FR-033) — но только в **подтверждённых** границах
  этого периода: неопределённая дата внутри диапазона оставляет период незавершённым
  целиком (FR-032d).
- Для источника со `scope = daily` поле `requires_audit` означает непроверенный справочник
  текущего состояния. Это состояние показывается как «нужна проверка» без выдуманной даты
  пропуска и без причины транспортной ошибки (FR-033b).
- Для `scope = daily` поля `last_checked_at` и `reason` описывают последнюю фактическую
  проверку. Старый `ok` без `coverage_version = 2` возвращается как `partial` с
  `requires_audit = 1`; новый проверенный полный ответ — как `ok`; последний реальный
  отказ — как `failed` с причиной. Дата проверки не является датой пропуска сессии.

`rows_written = 0` не определяет статус. Ответ с законным отсутствием закрывает только
область сохранённого доказательства; отсутствующий блок, чужая дата и нарушение контракта
оставляют область неполной.

**Чего в сводке нет:**

- состояния «соответствие неизвестно». Бумага, по которой позиции собирались, а теперь
  соответствие не строится, даёт **неуспех источника с причиной** — это неисправность, а
  не третья графа полноты (FR-010, FR-020a);
- конкретных значений наблюдений: это отчёт о полноте, а не просмотр данных;
- дивидендов: они ушли из ежедневного прогона (FR-008).

## Ошибки

| Код | Тело | Когда |
|---|---|---|
| `409` | `{"code": "calendar_empty"}` | хранилище пусто, первичная загрузка не выполнялась |
| `503` | `{"code": "worker_unavailable"}` | сборщик не ответил вовсе |

Разница между ними значима: пустое хранилище — состояние системы, недоступность сборщика —
неисправность, и показываются они по-разному.

- `next_expected_awaiting` (FR-054a) — `true`, когда `next_expected_session` — сегодня по
  Москве, порог `ingest_after_close` прошёл, а календарь дня ещё не подтвердил: идёт
  ожидание публикации. `calendar_retry_minutes` — интервал, с которым в это время
  переспрашивается календарь.
