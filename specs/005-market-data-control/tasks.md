# Tasks: Управление сбором рыночных данных

## Dependencies

**Порядок фаз**:

```text
Phase 1 → Phase 2 → Phase 3 (US1) → Phase 4 (US2) → Phase 5 (US3) → Phase 6 (US4) → Phase 7
```

**Блокирующие связи**:

- T003 → T005 → T025: понятие группы, затем запросы по группам, затем сводка;
- T003 → T015: выбор групп при запуске опирается на тот же реестр;
- T013 → T014 → T016 → T017: состояние, остановка, маршруты, подключение;
- T016 → T019: команда становится клиентом уже существующих маршрутов;
- T037 → T038 → T039: клиент, затем источник на нём, затем семантика пустого ответа;
- T037 → T047, T048: правила темпа и первой даты живут в клиенте;
- T038 → T049: пропуск собранных пар опирается на новый источник;
- T040 после T038: уборка имеет смысл, когда есть чем пересобрать;
- T051 после T035, T036, T037: сверять можно то, что исправлено.

**Независимость историй**: US1 даёт управление, US2 — видимость, US3 — данные, US4 —
аккуратность. US2 не требует US1: сводка полезна и до того, как догон стал управляемым, —
именно её отсутствие скрывало три дефекта из четырёх.

## Implementation Strategy

**MVP** — Phase 1 + Phase 2 + Phase 3 (US1). Догон перестаёт стартовать сам и становится
управляемым. Девятнадцать задач.

**Но полезнее начать с Phase 4 (US2).** Сводка самодостаточна и не зависит от US1: именно
её отсутствие позволило трём дефектам из четырёх прожить незамеченными. Если нужен
кратчайший путь к пользе, а не к MVP по определению, — Phase 2 плюс Phase 4.

## Phase 9: Оптимальность обращений — проверено 2026-09-10

Вопрос владельца «запросы оптимальным способом ходят?» проверен по фактам.

**Что нашлось.** У ISS есть официальный раздел открытых позиций
`analyticalproducts/futoi/securities.json?date=<дата>&latest=1`: колонки `ticker`,
`clgroup` (`FIZ`/`YUR`), `pos_long`, `pos_short`; один запрос отдаёт все инструменты за
дату. Значения сверены с формой на 2026-08-20 и **совпали до цифры** (SBRF: ФИЗ
132 880 / 103 791, ЮР 410 652 / 439 741; futoi даёт шорт со знаком минус). Соответствие
«код базового актива → тикер futoi» выводится из `series.json` однозначно для всех 201
кода: вечные серии дают тикер целиком (`SBERF`), остальные — `secid` без двух последних
знаков (`SRM7` → `SR`).

**Почему не переходим.** futoi покрывает 63 инструмента, из которых с нашими базовыми
активами пересекаются только **33 из 114** — самые ликвидные; остальные 81 всё равно
пришлось бы добирать формой. На сессию это 82 обращения вместо 114, около 28 %, ценой
второй ветки получения и разбора в источнике, который и так самый сложный в системе.
Плюс бесплатный доступ отдаёт futoi с задержкой 14 дней, то есть свежие сессии — всё
равно формой.

Первоначальная оценка «сокращение примерно стократное» была ошибкой счёта: она брала
число инструментов в ответе futoi, не проверив пересечение с нашим набором.
