# Quickstart: проверка управления сбором

Сценарии проверяют фичу на живом стенде. Полная готовность изменения проверяется командой
`scripts/check.sh` целиком — этот документ о другом: он показывает, что механизм делает то,
ради чего заведён.

## Предпосылки

```bash
cd deployments/docker-compose
docker compose up -d postgres backend-worker
```

В хранилище должны быть данные хотя бы за несколько сессий: догон отличается от первичной
загрузки по состоянию хранилища и на пустой базе намеренно не работает.

Команды выполняются внутри контейнера:

```bash
docker compose exec backend-worker python -m financial_ai.market_data.cli <команда>
```

## Управление догоном

### С1. Ежедневный сбор не запускает догон

**Что делаем**: при наличии дыры дожидаемся ежедневного прогона.

**Ожидаем**: текущая сессия собрана; ни одного обращения догона не выполнено; дыра осталась.

**Покрывает**: FR-001, SC-001.

### С2. Догон запускается человеком и его ход виден

**Что делаем**: запускаем догон, затем спрашиваем ход.

**Ожидаем**: видно, сколько сессий закрыто, сколько осталось и какая обрабатывается.

**Покрывает**: FR-002, FR-005.

### С3. Остановка мягкая

**Что делаем**: во время догона отдаём команду остановки.

**Ожидаем**: состояние переходит в `stopping`, текущая сессия доводится до конца, следующая
не начинается. Наполовину собранных дней нет.

**Покрывает**: FR-006, SC-002.

### С4. Продолжение с места остановки

**Что делаем**: после остановки запускаем догон снова.

**Ожидаем**: собираются только оставшиеся сессии; ни одна закрытая не собирается заново.

**Покрывает**: FR-007, SC-003.

### С5. Второй запуск отклоняется

**Что делаем**: при идущем догоне запускаем ещё один.

**Ожидаем**: отказ с указанием причины; идущий догон не нарушен.

**Покрывает**: FR-008.

### С6. Перезапуск не оставляет «идёт»

**Что делаем**: перезапускаем контейнер во время догона, затем спрашиваем ход и запускаем
догон снова.

**Ожидаем**: состояние `idle`; запуск принимается.

**Покрывает**: FR-009, SC-011.

### С7. Выбор групп и диапазона

**Что делаем**: запускаем догон, указав одну группу и диапазон уже окна.

**Ожидаем**: обращения идут только к выбранной группе; собираются только сессии диапазона.

**Покрывает**: FR-003, FR-004.

### С8. Диапазон шире окна обрезается

**Что делаем**: задаём диапазон, выходящий за окно.

**Ожидаем**: собираются только сессии окна, и обрезка видна в ответе.

**Покрывает**: FR-004.

### С9. Управление доступно не только из терминала

**Что делаем**: вызываем запуск, ход и остановку напрямую через внутренний интерфейс,
минуя команду.

**Ожидаем**: поведение то же. Канал пригоден для интерфейса без изменения поведения.

**Покрывает**: FR-010, SC-010.

## Сводка состояния

### С10. Сводка получается одной командой

**Что делаем**: запрашиваем сводку и сверяем одну группу с содержимым хранилища.

**Ожидаем**: покрытие, доля окна, границы периода и число дыр совпадают.

**Покрывает**: FR-011, FR-012, SC-004.

### С11. Собранное пустым отличимо от собранного

**Что делаем**: смотрим сводку до исправления позиций.

**Ожидаем**: у группы `positions` покрытие близко к полному, а доля значений — к нулю, и
расхождение выделено явно.

**Покрывает**: FR-013, SC-005.

### С12. Справочник не выглядит недобранным

**Что делаем**: смотрим строку группы `reference`.

**Ожидаем**: полей окна и покрытия нет вовсе, а не нули.

**Покрывает**: FR-014.

### С13. Значений в сводке нет

**Что делаем**: просматриваем весь ответ сводки.

**Ожидаем**: ни цен, ни объёмов, ни позиций — только числа о полноте.

**Покрывает**: FR-015.

## Исправленные источники

### С14. Диапазонные источники переживают прерывание

**Что делаем**: запускаем догон длинной дыры и останавливаем после первых сессий.

**Ожидаем**: индексы, USD, ставка и ЗКЦ уже собраны за весь диапазон.

**Покрывает**: FR-016, US3/AC1.

### С15. Brent собирается

**Что делаем**: собираем одну сессию и смотрим ряд Brent.

**Ожидаем**: фронтальный контракт найден, цена сохранена; предупреждения о ненайденном
контракте нет.

**Покрывает**: FR-019.

### С16. ЗКЦ содержит точки кривой

**Что делаем**: собираем одну сессию и смотрим ряды ЗКЦ.

**Ожидаем**: сохранены точки по срокам, включая объявленные в конфигурации признаков
модели; параметров модели Нельсона-Сигеля вместо них нет.

**Покрывает**: FR-020.

### С17. Пустые строки позиций убраны

**Что делаем**: после применения миграций смотрим позиции.

**Ожидаем**: строк без единого значения нет; строки со значениями сохранены.

**Покрывает**: FR-020a, SC-009.

### С18. Позиции содержат значения

**Что делаем**: собираем одну сессию и смотрим позиции.

**Ожидаем**: значения непусты хотя бы по части инструментов.

**Покрывает**: FR-017, US3/AC2.

### С19. Пустой ответ фиксируется как неуспех

**Что делаем**: имитируем источник, вернувший строки без значений.

**Ожидаем**: прогон записан неуспешным с причиной, а не успешным с формулировкой о
частичном покрытии.

**Покрывает**: FR-018, US3/AC5.

## Аккуратность обращений

### С20. Бесполезных обращений не осталось

**Что делаем**: считаем обращения на одну дату до и после исправлений.

**Ожидаем**: обращений, заведомо не приносящих данных, нет.

**Покрывает**: FR-022, SC-007.

### С21. Недоступный источник перестаёт опрашиваться

**Что делаем**: имитируем недоступность источника на нескольких сессиях подряд.

**Ожидаем**: после исчерпания повторов обращения к нему в этом прогоне прекращаются.

**Покрывает**: FR-024.

## Живые сверки

Отдельные команды, запускаемые человеком. **В гейт не входят**: сеть в среде сборки
недоступна, и гейт стал бы недетерминированным (FR-026).

```bash
… cli verify-cbr        # разбор страниц Банка России, включая точки ЗКЦ
… cli verify-brent      # адрес срочного рынка и поиск фронтального контракта
… cli verify-positions  # настоящий источник позиций
```

**Ожидаем**: каждая подтверждает исправление живым ответом источника.

**Покрывает**: FR-025, SC-008.

## Готовность изменения

```bash
scripts/check.sh
```

Запускать целиком. Частичные прогоны в этом проекте уже пропускали дефекты.
