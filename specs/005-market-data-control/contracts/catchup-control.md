# Contract: управление догоном

Внутренний интерфейс `backend-worker`, рядом с существующими `/internal/health` и
`/internal/sync`. Тот же образец, что у `/internal/sync`: обращение состоялось — значит
`200`, а исход описан телом ответа; `5xx` означал бы отказ самого worker'а.

**Наружу не выставляется.** У контейнера `backend-worker` нет проброса портов: он доступен
только внутри сети развёртывания. Этот интерфейс управляет обращениями к бирже, и
публичным быть не должен.

Команда `market_data.cli` становится **тонким клиентом** над этими маршрутами: она их
вызывает, а не выполняет сбор сама. Интерфейс подключился сюда же — через публичные
маршруты `backend-api`, которые передают команды этому интерфейсу и наружу его не выносят
(фича 006, `specs/006-market-data-ui/contracts/market-data-api.md`).

---

## `POST /internal/catchup` — запустить

```json
{
  "groups": ["quotes", "aggregates"],
  "date_from": "2026-06-01",
  "date_till": "2026-08-28"
}
```

| Поле | Обязательно | Умолчание | Смысл |
|---|---|---|---|
| `groups` | нет | все группы | Какие группы источников догонять |
| `date_from` | нет | начало окна | Начало диапазона |
| `date_till` | нет | конец окна | Конец диапазона |

Диапазон **обрезается по окну**, и обрезка видна в ответе: сессия старше окна в набор всё
равно не попадёт.

### `200 OK` — запуск принят

```json
{
  "status": "running",
  "groups": ["quotes", "aggregates"],
  "date_from": "2026-06-01",
  "date_till": "2026-08-28",
  "clamped": true,
  "requested_sessions": 62
}
```

`clamped` — признак того, что заданный диапазон был обрезан по окну.

### `200 OK` — запускать нечего

```json
{ "status": "idle", "requested_sessions": 0, "reason": "пропущенных сессий нет" }
```

### `409 Conflict` — догон уже идёт

```json
{ "detail": { "code": "catchup_already_running", "message": "догон уже выполняется" } }
```

Отклонение, а не присоединение: два одновременных сбора писали бы одни и те же строки и
удваивали обращения к бирже. Это единственное отличие от образца `/internal/sync`, где
присоединение уместно, потому что синхронизация счёта идемпотентна и коротка.

### `422` — запрос неверен

| Ситуация | `detail.code` |
|---|---|
| Неизвестная группа | `unknown_group` |
| Дата не разбирается | `invalid_date` |
| `date_from` позже `date_till` | `invalid_range` |
| В хранилище нет наблюдений | `backfill_required` |

Последнее — не ошибка ввода, а состояние системы: на пустом хранилище нужна первичная
загрузка, а не догон.

## `GET /internal/catchup` — ход работы

```json
{
  "status": "running",
  "groups": ["quotes", "aggregates"],
  "date_from": "2026-06-01",
  "date_till": "2026-08-28",
  "requested": 62,
  "closed": 17,
  "failed": 1,
  "remaining": 44,
  "current": "2026-06-25",
  "started_at": "2026-09-04T08:12:03+00:00",
  "finished_at": null
}
```

| `status` | Что означает |
|---|---|
| `idle` | догон не запускался или процесс перезапускался |
| `running` | идёт |
| `stopping` | остановка запрошена, текущая сессия доводится до конца |
| `stopped` | остановлен по команде |
| `finished` | дошёл до конца диапазона |
| `failed` | прерван ошибкой; причина в `reason` |

После перезапуска компонента возвращается `idle`: состояние живёт в процессе и вместе с
ним исчезает. Зависшего «идёт» не бывает по устройству — что собрано, видно по данным.

### `reason` — причина, пригодная для показа

`reason` — **короткая человекочитаемая фраза**, а не текст исключения. Подробности
остаются в журнале, куда их уже пишет `logger.exception`.

Различие не косметическое. Текст исключения `httpx` содержит адрес, по которому шло
обращение, и этот адрес может быть внутренним. Пока причину читал человек в терминале
стенда, это было терпимо; с появлением интерфейса тот же текст ушёл бы на экран, а
показывать конфигурацию и внутренние адреса пользователю нельзя (фича 006, FR-043).

```json
{ "status": "failed", "reason": "источник данных недоступен", "closed": 17, "failed": 1 }
```

## `DELETE /internal/catchup` — остановить

### `200 OK`

```json
{ "status": "stopping", "current": "2026-06-25" }
```

**Остановка мягкая**: текущая сессия доводится до конца, дальнейшие не начинаются. День,
собранный наполовину, неотличим от собранного полностью — поэтому обрывать сессию нельзя.

### `200 OK` — останавливать нечего

```json
{ "status": "idle" }
```

Не ошибка: запрос состоялся, останавливать оказалось нечего.

## Что этот интерфейс не делает

- **не запускает первичную загрузку**: на пустом хранилище отвечает `backfill_required`.
  Первичная загрузка — длинная операция с другим способом обращения к бирже, и решение о
  её запуске принимает человек;
- **не собирает текущую сессию**: она собирается ежедневным циклом автоматически;
- **не материализует набор и не запрашивает ранжирование**: это делает цикл;
- **не показывает данные**: для этого сводка, см.
  [coverage-report.md](./coverage-report.md).
