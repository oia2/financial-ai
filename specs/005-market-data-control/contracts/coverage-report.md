# Contract: сводка состояния данных

Ответ на вопрос «что у нас есть» — по группам источников, без вывода конкретных значений.

Доступна двумя путями: маршрутом внутреннего интерфейса `backend-worker` и командой
`market_data.cli coverage`, которая его вызывает. Интерфейс подключился сюда же — через
публичные маршруты `backend-api`, которые передают чтение этому маршруту (фича 006,
`specs/006-market-data-ui/contracts/market-data-api.md`).

---

## `GET /internal/coverage`

Параметр `asof` — дата решения, от которой отсчитываются окна. По умолчанию — последняя
завершённая сессия календаря.

### `200 OK`

```json
{
  "asof_date": "2026-09-02",
  "catchup_window": {
    "date_from": "2025-06-10",
    "date_till": "2026-09-02",
    "sessions": 314
  },
  "groups": [
    {
      "group": "quotes",
      "has_history": true,
      "window_sessions": 314,
      "sessions_covered": 224,
      "coverage_ratio": 0.713,
      "period_from": "2025-06-10",
      "period_till": "2026-09-02",
      "gaps": 90,
      "rows_total": 57049,
      "rows_with_values": 57049,
      "value_ratio": 1.0,
      "looks_collected_but_empty": false
    },
    {
      "group": "positions",
      "has_history": true,
      "window_sessions": 82,
      "sessions_covered": 82,
      "coverage_ratio": 1.0,
      "period_from": "2026-05-08",
      "period_till": "2026-09-02",
      "gaps": 0,
      "rows_total": 21320,
      "rows_with_values": 5,
      "value_ratio": 0.0002,
      "looks_collected_but_empty": true
    },
    {
      "group": "reference",
      "has_history": false,
      "rows_total": 506,
      "rows_with_values": 506,
      "value_ratio": 1.0,
      "looks_collected_but_empty": false
    }
  ]
}
```

| Поле верхнего уровня | Смысл |
|---|---|
| `asof_date` | дата решения, от которой отсчитаны окна |
| `catchup_window` | границы и размер окна **догона**: `date_from`, `date_till`, `sessions` |

Окно догона — не то же, что окно группы: у групп они разные (314 сессий у котировок, 82 у
позиций), а планирование прогона считает своё
(`Settings.catchup_window_sessions`). Интерфейс предзаполняет им поля диапазона в форме
запуска, поэтому окно должно приходить из того же источника, каким пользуется планирование,
а не выводиться из строк сводки.

| Поле группы | Смысл |
|---|---|
| `group` | группа источников |
| `has_history` | ложь для справочников текущего состояния |
| `window_sessions` | размер окна группы; отсутствует при `has_history: false` |
| `sessions_covered` | сессий окна, за которые есть хоть одна строка |
| `coverage_ratio` | доля окна |
| `period_from`, `period_till` | границы имеющегося периода |
| `gaps` | число пропущенных сессий окна |
| `rows_total` | строк за окно |
| `rows_with_values` | из них со значениями |
| `value_ratio` | доля непустых |
| `looks_collected_but_empty` | покрытие есть, а значений практически нет — тот самый дефект |

---

## Почему два числа, а не одно

Строка `positions` в примере — не выдумка, это состояние хранилища на 2026-09-03.

```text
coverage_ratio = 1.00     ← «собрано полностью»
value_ratio    = 0.0002   ← значений 5 из 21 320
```

Отчёт, показывающий только покрытие, объявил бы группу собранной. Именно так дефект и
прожил незамеченным: лог сообщал «получено 260, записано 260», сводки не было, а
несоответствие обнаружилось лишь прямым запросом к таблице.

**Поэтому `value_ratio` обязателен**, а не желателен: без него сводка воспроизводит ту
самую слепоту, ради устранения которой заводится.

Расхождение называет **сам ответ**, полем `looks_collected_but_empty`: покрытие
положительно, а доля значений ниже одного процента. Порог считает сервер и только он.
Отдай ответ два числа и промолчи о выводе — порог пришлось бы повторить в команде и ещё раз
в интерфейсе, и при первом же уточнении они разошлись бы.

---

## Инварианты

- **Справочники не выглядят недобранными.** У группы без оси сессий полей окна и покрытия
  нет вовсе, а не ноль: ноль читался бы как «ничего не собрано».
- **Конкретные значения не выводятся.** Это отчёт о полноте, а не просмотр данных: ни
  цен, ни объёмов, ни позиций в ответе нет.
- **Числа согласованы с хранилищем.** Сводка вычисляется по данным при каждом обращении и
  нигде не кэшируется: хранимая сводка могла бы разойтись с фактом, а вычисленная — нет.
- **Пустая группа отличима от отсутствующей.** Группа, за которую нет ни строки,
  показывает нули, а не исчезает из ответа.

## Команда

```
financial_ai.market_data.cli coverage [--asof YYYY-MM-DD]
```

```text
состояние на 2026-09-02

группа        окно   покрыто   доля    значений   период
quotes         314       224   71.3%     100.0%   2025-06-10 … 2026-09-02
aggregates     314       224   71.3%     100.0%   2025-06-10 … 2026-09-02
global         314         5    1.6%     100.0%   2026-08-26 … 2026-09-02
positions       82        82  100.0%       0.0%   2026-05-08 … 2026-09-02
reference        —         —       —      100.0%   справочник, истории нет

внимание: у группы positions покрытие 100.0% при доле значений 0.0%
```

Последняя строка — не украшение. Расхождение между покрытием и долей значений выделяется
явно: именно оно означает «собрано, но пусто», и именно его человек не заметит в таблице
чисел.

**Коды возврата**: `0` — сводка получена, независимо от того, полны данные или нет; `1` —
получить не удалось. Отдельного кода для «данные неполны» нет: команда отвечает на вопрос,
а не выносит вердикт.
