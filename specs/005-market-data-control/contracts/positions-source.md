# Contract: источник позиций по фьючерсам

Описывает **обмен с источником**, а не наш интерфейс: это контракт, который биржа диктует
нам. Записан здесь, потому что от него зависят требования об аккуратности обращений, а не
только форма данных.

Происхождение — `pipelines/moex_futures_positions/` исследовательского репозитория,
ревизия `f07295e`. Перенос выполняется по тем же правилам, что и остальные одиннадцать
источников: логика получения и разбора сохраняется, запись в CSV заменяется записью в
PostgreSQL, инженерия признаков не переносится.

---

## Чем этот источник отличается от остальных

| | Остальные одиннадцать | Позиции |
|---|---|---|
| Хост | биржевой интерфейс данных | сайт биржи, раздел срочного рынка |
| Способ запроса | параметры в адресе | форма, тело запроса по шаблону |
| Формат ответа | JSON | HTML |
| Единица обращения | **дата** — все бумаги сразу | **инструмент и дата** |
| Обращений на сессию | 1–3 | по числу инструментов |

Последняя строка и есть причина, по которой требования FR-024a — FR-024d существуют.
Источник становится самым нагруженным в системе, и без ограничений сбор истории
превращается в поток запросов к чужому бесплатному серверу.

---

## Что переносится

- **обмен формой**: тело запроса по шаблону, дата в параметрах, собственные повторы;
- **разбор ответа**: несмотря на расширение в адресе, приходит **HTML**. Библиотека разбора
  в проекте уже есть — ей же разбираются страницы Банка России, новой зависимости не
  появляется;
- **сопоставление акции с фьючерсным контрактом**: без него неизвестно, чьи позиции
  спрашивать. Источник соответствия **другой, чем в оригинале** — см. ниже;
- **разделение на ФИЗ и ЮР**;
- **поиск первой доступной даты** инструмента.

## Что не переносится

- **запись в CSV и раскладка файлов** — у нас PostgreSQL, как и у остальных источников;
- **кэш первой доступной даты отдельным файлом** — выводится из данных, по тому же
  правилу, что и прогресс первичной загрузки: отдельное состояние может разойтись с фактом;
- **файл соответствий `equity_tickers.csv`** — соответствие строится из ISS, см. ниже;
- **отображение строк таблицы по позиции** — строка ищется по названию, см. ниже;
- **политика алиасов и сшивка рядов** — инженерия признаков, остаётся на стороне модели.
  Это уже было записано при переносе 003 и остаётся верным.

## Соответствие акции и контракта

Оригинал читает его из `data_2/raw/metadata/equity_tickers.csv`. Этого файла в подключённом
репозитории нет, и правилом код контракта не выводится: `SBER → SBRF_F`, `GAZP → GAZR_F`,
`NVTK → NOTKM_F`.

**Соответствие строится из ISS** — того же интерфейса, которым идёт остальной сбор:

1. `statistics/engines/futures/markets/forts/series.json` даёт `underlying_asset` (тикер
   акции) и `asset_code`;
2. код инструмента на странице открытых позиций — `<asset_code>_F`;
3. если у акции несколько кодов, берётся тот, у которого больше суммарный открытый интерес
   (`PREVOPENPOSITION` из `engines/futures/markets/forts/securities.json`).

Проверено на живых ответах: 96 базовых активов из 104 имеют контракт в списке инструментов
страницы, и все спорные случаи правило разрешает в пользу классического контракта —
`SBRF_F`, а не вечного `SBERF_F`. Обоснование и отвергнутые варианты — research.md §11.

**Акция без контракта — не ошибка**: обращений по ней не выполняется вовсе (FR-022).

## Разбор ответа

| Что | Как ищется |
|---|---|
| Дата данных | `span.text-center`, текст вида «Данные на 28 августа 2026» |
| Таблица | `table.table1._full-width.table1` |
| Строка открытых позиций | **по названию** «Количество договоров (контрактов)» |
| Столбцы | ФИЗ длинные, ФИЗ короткие, ЮР длинные, ЮР короткие, совокупный объём |

Строка ищется по названию, а не по позиции, как в оригинале: на сегодняшней странице
порядок строк другой, и позиционное отображение записало бы число держателей позиций
в столбец открытых позиций. Обоснование — research.md §12.

**Дата ответа сверяется с запрошенной.** Ответ за другую дату — не данные запрошенной
сессии, и записывать его как наблюдение о ней означало бы передатирование.

## Правила обращения

Не пожелания, а условия, при которых источник допустимо использовать.

| Правило | Требование | Почему |
|---|---|---|
| Темп ограничен | FR-024a | Между пачками обращений выдерживается пауза |
| Размер пачки и пауза настраиваются | FR-024d | Допустимая нагрузка — вопрос эксплуатации, а не свойство кода |
| Несуществующие периоды не запрашиваются | FR-024b | До первой доступной даты инструмента данных нет и быть не может |
| Первая доступная дата определяется однократно | FR-024b | Иначе поиск повторяется при каждом прогоне |
| Собранная пара «инструмент — дата» не запрашивается снова | FR-024c | Без этого повторный догон стоит столько же, сколько первый |
| Недоступный источник перестаёт опрашиваться в пределах прогона | FR-024 | Иначе каждая сессия стоит семь обращений впустую |

**Правило FR-024c требуется именно здесь.** Для источников с единицей обращения «дата» оно
следует из правил догона: сессия собрана — сессия не запрашивается. Здесь единица мельче
сессии, и «сессия собрана» перестаёт означать «все инструменты собраны».

---

## Пустой ответ — это неуспех

Ответ, в котором нет ни одного значения там, где источник обязан их приносить,
записывается как **неуспех с причиной**, а не как успех (FR-018).

Так сформулировано не из строгости. Прежняя реализация писала 260 строк пустых значений на
каждую сессию и сообщала «получено 260, записано 260 (покрытие частичное — это норма)».
Формулировка про частичное покрытие верна для настоящей частичности — позиции по части
инструментов действительно отсутствуют, — но она же скрыла дефект, при котором значений не
было **вообще**: 5 непустых строк на 57 029.

Различие проверяемо: настоящая частичность даёт непустые значения хотя бы по части
инструментов, дефект даёт ноль.

## Проверка

Живой сверкой, отдельной командой, вне гейта (FR-025, FR-026):

```
financial_ai.market_data.cli verify-positions
```

Подтверждает на настоящем ответе источника: обмен состоялся, разбор дал значения,
сопоставление с контрактом сработало. Подделка этого по определению не ловит — все четыре
дефекта фичи были расхождением с настоящим источником, а тесты на подделках проходили.
