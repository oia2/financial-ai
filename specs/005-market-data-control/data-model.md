# Data Model: Управление сбором рыночных данных

Фича **не добавляет ни одной таблицы**. Она добавляет два вычисляемых понятия, одно
состояние, живущее в процессе, и одну разовую уборку.

## 1. Общие правила

Правила фич 003 и 004 действуют без изменений: `Decimal` в домене, `NUMERIC(28,9)` в
хранилище, строки в JSON, пропуск остаётся пропуском, календарь — источник истины о
сессиях, пропуск вычисляется, а не хранится.

---

## 2. Группа источников — справочник в коде

Единица выбора при запуске догона и единица строки в сводке. Не хранится в БД: это
свойство кода, а не данных.

| Группа | Что входит | Ось | Окно |
|---|---|---|---|
| `quotes` | дневные котировки | сессии × ценовые ряды | окно цен |
| `aggregates` | обороты, число сделок, средневзвешенная цена | сессии × ценовые ряды | окно цен |
| `global` | индексы, веса в индексе, USD, ключевая ставка, точки ЗКЦ, Brent | сессии × ряды | окно глобальных рядов |
| `positions` | позиции ФИЗ и ЮР по фьючерсам | сессии × активы | окно позиций |
| `reference` | секторы эмитентов | без оси сессий | — |

**Почему именно так**: это семейства, которыми оперирует модель, и в которых человек
задаёт вопрос «что у нас есть». Деление по одному источнику дало бы двенадцать пунктов,
пять из которых человек всё равно читает как одни «глобальные ряды».

**Свойство группы, важное для отчёта**: у каждой группы есть **способ определить непустоту
строки**. Для котировок это цена закрытия, для позиций — любое из четырёх значений, для
глобальных рядов — значение ряда. Без этого сводка не отличит собранное от собранного
пустым.

---

## 3. Сводка состояния — вычисляется, не хранится

Одна строка на группу.

| Поле | Смысл |
|---|---|
| `group` | группа источников |
| `sessions_covered` | сессий окна, за которые есть хоть одна строка |
| `window_sessions` | размер окна группы в сессиях |
| `coverage_ratio` | доля окна |
| `period_from`, `period_till` | границы имеющегося периода |
| `gaps` | число пропущенных сессий окна |
| `rows_total` | строк в группе за окно |
| `rows_with_values` | из них со значениями |
| `value_ratio` | доля непустых |
| `has_history` | ложь для справочников: группа без оси сессий не бывает недобранной |

**Ключевое поле — `value_ratio`.** Дефект позиций жил в зазоре между `coverage_ratio` = 1.0
и `value_ratio` ≈ 0.0001. Отчёт без второго числа объявил бы группу собранной.

**Чего в сводке нет**: конкретных значений наблюдений. Это отчёт о полноте, а не просмотр
данных (FR-015).

## 4. Задание догона — состояние в процессе

Живёт в памяти работающего компонента. **В хранилище не попадает** — см. research.md §2.

| Поле | Смысл |
|---|---|
| `status` | `idle`, `running`, `stopping`, `stopped`, `finished`, `failed` |
| `groups` | выбранные группы; пусто — все |
| `date_from`, `date_till` | выбранный диапазон после обрезки по окну |
| `requested` | сессии к сбору |
| `closed`, `failed_sessions` | исход по сессиям |
| `current` | обрабатываемая сейчас сессия |
| `started_at`, `finished_at` | отметки времени |
| `stop_requested` | признак мягкой остановки |

**Переходы**:

```text
idle ──запуск──▶ running ──▶ finished
                    │
                    ├──остановка──▶ stopping ──текущая сессия дошла──▶ stopped
                    └──ошибка──────▶ failed

перезапуск процесса ──▶ idle   (из любого состояния)
```

**Почему перезапуск возвращает в `idle`**: состояние живёт в процессе, значит вместе с ним
и исчезает. Зависшего «идёт» не бывает по устройству.

**Мягкая остановка**: `stop_requested` проверяется **между** сессиями. Начатая сессия
доводится до конца — день, собранный наполовину, неотличим от собранного полностью.

**Единственность**: запуск при `running` или `stopping` отклоняется. Двух одновременных
сборов быть не должно: они писали бы одни и те же строки и удваивали обращения к бирже.

## 5. Результат прогона сбора — без изменений

Таблица `market_ingest_run` (фича 003, поле `trigger` из фичи 004) остаётся как есть.
История прогонов уже там, и второе хранилище истории не заводится.

Одно уточнение в **семантике статуса**: полное отсутствие значений там, где источник обязан
их приносить, записывается как `failed` с причиной, а не как `ok` (FR-018). Раньше такой
исход считался успехом с формулировкой про частичное покрытие — из-за неё дефект и прожил
незамеченным.

## 6. Разовая уборка пустых позиций

Не сущность, а однократное изменение данных.

**Что удаляется**: строки `market_futures_position`, в которых **все четыре значения**
пусты. Строк таких 57 029 из 57 034.

**Что остаётся**: строки, где есть хоть одно значение. Их 5, и дефект их не касался.

**Почему миграцией**: выполняется один раз и сама себя фиксирует. Отдельная команда могла
бы не выполниться или выполниться дважды.

**Что произойдёт дальше**: сессии, потерявшие все строки позиций, станут для сводки
непокрытыми по этой группе — и следующий догон соберёт их заново, уже правильным
источником. Это и есть цель уборки.

---

## 7. Чего в этой модели нет

- **таблицы заданий догона**: состояние живёт в процессе, история прогонов уже есть;
- **хранимой сводки**: покрытие вычисляется по данным и разойтись с ними не может;
- **понятия «непригодные данные»**: отвергнуто владельцем в пользу удаления;
- **новых полей у наблюдений**: группы и непустота выводятся из существующих столбцов.
