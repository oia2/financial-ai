# Contract: состояния интерфейса и соответствие артефакту

Источник истины — проект Open Design «Портфель FINANCIAL AI»: `market-data.html`,
`financial-ai-portfolio.html`, `market-data-states.html`, `market-data-design.md` и файлы
`design-assets/`. Соответствие проверяется **сопоставлением состава и имён элементов**, а
не общим впечатлением (Принцип VIII).

Имена в колонке «Элемент артефакта» — значения `data-od-id` из артефакта. Они же остаются
опорой при сверке `/speckit-converge`.

**Отступление, зафиксированное с причиной**: артефакт объявляет межстраничные переходы

приложении переход между разделами запускается `document.startViewTransition()`; имена
`view-transition-name` (`app-header`, `process-rail`) и длительности 140/240 мс
сохраняются (research.md, R4).

## 3. Шесть состояний прогона

Соответствуют превью `review-<status>` на листе `market-data-states.html`.

| Состояние | Показ | Действие |
|---|---|---|
| `idle` | «Не запущен», пояснение про сбор только пропусков | «Настроить запуск» |
| `running` | `closed из requested`, «Осталось обработать», «Не закрыто», текущая сессия с ориентиром длительности | «Остановить» |
| `stopping` | «Остановка запрошена», «Завершаем сессию», спокойный индикатор с циклом 4,8 с | Действий нет |
| `stopped` | Подтверждённая остановка, сохранённые счётчики | «Продолжить догон» |
| `finished` | «Догон завершён»; при `failed > 0` — «Есть незакрытые сессии» и уведомление о пропусках без отметки успеха | «Продолжить догон», если незакрытые есть |
| `failed` | Причина из `reason`, сохранённый прогресс | «Продолжить догон» |

Индикатор хода: `role="progressbar"` с `aria-valuemin=0`, `aria-valuemax=requested`,
`aria-valuenow=closed` и текстовым описанием «Закрыто N из M; не закрыто K; осталось
обработать L». Закрытые и незакрывшиеся — два разных сегмента (FR-030). Длина подтверждённой
части меняется за 700 мс и только при новом `closed` от сервера (FR-031).

## 4. Десять пограничных случаев

Соответствуют карточкам `edge-<id>` артефакта.

| Случай | Что показывается | Требование |
|---|---|---|
| `anomaly` | Полное покрытие при нулевой доле значений: уведомление над сводкой и выделенная строка | FR-016 |
| `empty` | «Хранилище пусто»: нужна первичная загрузка, догон недоступен, без сообщения об аварии | FR-026 |
| `nothing` | «Догонять нечего»: спокойное подтверждение, кнопка запуска не показывается | FR-038 |
| `already-running` | Повторный запуск отклонён; счётчики идущего прогона сохранены | FR-039 |
| `invalid-group` | Неизвестная группа: отказ по устаревшему запросу | FR-038 |
| `invalid-date` | Дата не разбирается: ошибка у поля, значение сохранено | FR-041 |
| `invalid-range` | Начало позже конца: форма не отправляется, фокус к началу диапазона | FR-041 |
| `clamped` | Введённый и принятый диапазоны рядом, сообщение не исчезает | FR-040 |
| `restart` | После ответа `idle` прежнее «идёт» отбрасывается; причина названа возможной | FR-035 |
| `partial` | Завершено с пропусками: без общей отметки успеха, продолжение доступно | FR-033 |

## 5. Доступность и адаптивность

| Правило | Требование |
|---|---|
| Панели (`dialog`) закрываются по Escape и возвращают фокус вызвавшей кнопке | FR-053 |
| Управляющие элементы не ниже 44 px | FR-054 |
| Числа, даты и доли — моноширинные, с выравниванием разрядов | FR-051 |
| Ошибка и особое состояние передаются текстом, а не только цветом | FR-052 |
| `prefers-reduced-motion` отключает движение без потери смысла состояний | FR-055 |
| Узкий экран перестраивает таблицу в строки, горизонтальной прокрутки нет | FR-056 |
| Малый индикатор активности не читается как процент готовности сессии | FR-057 |

Утилита `.sr-only` — исключение, допускаемое Принципом VIII: артефакт использует класс, но
правил для него не содержит, поэтому он остаётся в `app.css` рядом с уже перенесённым
случаем из фичи 001.

## 6. Результат сверки 2026-09-10

Сверка шла в два прохода. Первый сравнивал **имена классов** и нашёл два расхождения;
второй сравнивал **состав элементов** по `data-od-id` и нашёл ещё одно — кнопку запуска в
заголовке (`configure-catchup`), которой в реализации не было вовсе. Первый проход её не
увидел: кнопка использует класс `primary-button`, встречающийся в других местах, и разницы
в наборе классов не возникло.

**Вывод для следующих сверок: сравнение по классам недостаточно.** Сопоставлять нужно
элементы по `data-od-id`, как и требует заголовок этого документа.

После исправления (задачи T051–T053) из артефакта не перенесены **два** элемента, оба —
маркеры прототипа:

| Класс | Что это | Почему не перенесено |
|---|---|---|
| `prototype-label` | Подпись «Прототип» у марки | Приложение прототипом не является; подпись утверждала бы неправду |
| `market-footer` | Подвал «Сводка — снимок стенда. Ход догона — демонстрационный» | Та же причина: в продукте сводка — не снимок стенда, а ход догона — не демонстрация |

### Отступления по тексту

| Артефакт | В продукте | Причина |
|---|---|---|
| «Снимок стенда» над датой в заголовке | «Состояние на» | Та же причина, что у подвала: в продукте это не снимок стенда, а состояние хранилища на дату решения |
| Состояние `finished` подписано «Диапазон завершён» | «Догон завершён» | Решение владельца проекта от 2026-09-10. Подпись безопасна: при незакрытых сессиях состояние называется иначе — «Есть незакрытые сессии», — поэтому «Догон завершён» никогда не показывается поверх пропусков (FR-033) |

Оба текстовых отступления **подлежат переносу в Open Design**: по Принципу VIII оформление
и копирайт правятся сначала в инструменте. Сделать это в момент реализации не удалось —
сервер Open Design в сессии 2026-09-10 не подключился. До правки артефакта источником
истины по этим двум подписям остаётся эта таблица.

Оба отступления **вынужденные**: артефакт описывает их текстом, относящимся к
демонстратору, и перенос сохранил бы разметку ценой ложного утверждения на экране. Место
подвала в композиции при этом свободно — если он нужен продукту, его содержание сначала
правится в Open Design (Принцип VIII), и только затем переносится.

Идентификаторы `data-od-id` в код не переносятся — как и в фиче 001: они принадлежат
инструменту проектирования и служат опорой сверки, а не разметке продукта.

Третье отступление — способ запуска перехода между разделами — описано в разделе 1.

## 7. Что из артефакта не переносится

`design-assets/market-data-runtime.js` — демонстратор: счётчики хода, список дней, причины
ошибок, упрощённый календарь будних дней и сохранение прогона в `localStorage`. Ни одна из
этих сущностей в приложение не переходит; все числа приходят с сервера (FR-036,
research.md R7). Превью на листе состояний изолированы и служат только сверке.
