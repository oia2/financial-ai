# Data Model: интерфейс рыночных данных

Новых таблиц и миграций фича не вводит: всё показанное на экране уже собрано фичами 003–005.
Здесь описаны сущности **представления** — то, чем оперирует интерфейс, и правила, по
которым значение превращается в показ.

---

## 1. Сводка полноты (`CoverageReport`)

Читается целиком, одним ответом. Отчёт о полноте, не просмотр данных: конкретных значений
наблюдений в нём нет и быть не должно (FR-008).

| Поле | Тип | Смысл и правила показа |
|---|---|---|
| `asof_date` | дата | Дата решения, от которой отсчитаны окна. Показывается как «Снимок стенда» |
| `catchup_window.date_from` / `date_till` | дата | Границы доступного окна догона. Предзаполняют поля диапазона в форме запуска |
| `catchup_window.sessions` | целое | Размер окна в торговых сессиях |
| `groups[]` | список | Ровно пять групп, порядок — из ответа сервера, не пересортировывается |

### Группа (`GroupCoverage`)

| Поле | Тип | Правила показа |
|---|---|---|
| `group` | строка | Идентификатор: `quotes`, `aggregates`, `global`, `positions`, `reference`. Показывается под названием |
| `title` | строка | Название с заглавной первой буквы (research.md, R6) |
| `has_history` | булево | `false` — группа не имеет истории по природе |
| `window_sessions` | целое \| отсутствует | Отсутствует у группы без истории. **Ноль вместо отсутствия недопустим** (FR-014) |
| `sessions_covered` | целое \| отсутствует | То же |
| `coverage_ratio` | доля 0…1 \| `null` | Показывается процентом. Не окрашивается как успех (FR-010) |
| `period_from` / `period_till` | дата \| `null` | Границы имеющихся данных, не границы окна |
| `gaps` | целое \| отсутствует | Непокрытые сессии = `window_sessions − sessions_covered` |
| `rows_total` | целое \| `null` | `null` показывается прочерком с объяснением, не нулём (FR-015) |
| `rows_with_values` | целое \| `null` | То же |
| `value_ratio` | доля 0…1 \| `null` | Доля строк со значениями. Отдельная от покрытия характеристика (FR-009) |
| `looks_collected_but_empty` | булево | Признак расхождения. Включает крупное уведомление над сводкой и выделение строки (FR-016) |

**Правила, которые нельзя нарушить**

- Покрытие и доля значений — две колонки, а не одно число: интегрального рейтинга нет
  (FR-012).
- Зелёный в колонке значений означает наличие значений в **записанных строках**, а не их
  достоверность и не полноту окна (FR-011).
- У группы без истории числовые поля истории отсутствуют, а в ячейке стоит объяснение
  неприменимости (FR-014).
- Перечень дат пропусков не изобретается: сервер отдаёт только их количество.

## 2. Состояние прогона (`CatchupState`)

Единственный источник — ответ сервера. Локально сохранённое представление источником
истины не является (FR-036).

| Поле | Тип | Правила показа |
|---|---|---|
| `status` | одно из шести | См. таблицу переходов ниже |
| `groups[]` | список строк | Пять из пяти показываются как «Все группы» |
| `date_from` / `date_till` | дата \| `null` | **Принятый** диапазон: первая и последняя сессия плана. Может отличаться от границ окна, если сервер сузил его до фактических пропусков |
| `clamped` | булево | `true` — рядом показывается введённый пользователем диапазон |
| `requested` | целое | Число сессий плана **из ответа**. Суммой пропусков по группам не вычисляется (FR-029) |
| `closed` | целое | Закрытые сессии. Основа индикатора хода |
| `failed` | целое | Незакрывшиеся. Показываются отдельно, в закрытые не включаются (FR-030) |
| `remaining` | целое | `requested − closed − failed`. Не называется «все незакрытые» |
| `current` | дата \| `null` | Обрабатываемая сессия |
| `started_at` / `finished_at` | момент \| `null` | Начало и конец прогона |
| `reason` | строка \| `null` | Причина прерывания, пригодная для показа. Формулируется сервером, не интерфейсом (FR-034, research.md R2.3) |

### Переходы состояний

```text
        ┌──────────────────────── idle ◄───────────────────────┐
        │                          │                           │
        │                     запуск принят                    │ перезапуск
        │                          ▼                           │ компонента
        │                       running ──── ошибка ──► failed ─┤
        │                          │                            │
        │                   остановка запрошена                 │
        │                          ▼                            │
        │                      stopping                         │
        │                          │                            │
        │                 текущая сессия закрыта                │
        │                          ▼                            │
        └── новый запуск ◄───── stopped                         │
                                                                │
            running ── диапазон исчерпан ──► finished ──────────┘
```

| Состояние | Что видно | Действие |
|---|---|---|
| `idle` | «Не запущен», настройка запуска | «Настроить запуск» |
| `running` | `closed` из `requested`, `remaining`, `failed`, `current` | «Остановить» |
| `stopping` | «Завершаем текущую сессию» | Действий нет: ни повторной остановки, ни возобновления (FR-024) |
| `stopped` | Подтверждённая остановка, сохранённые счётчики | «Продолжить догон» |
| `finished` | Диапазон завершён; при `failed > 0` — явные пропуски без отметки успеха (FR-033) | «Продолжить догон», если есть незакрытые |
| `failed` | Причина из `reason`, сохранённый прогресс | «Продолжить догон» |

**Правила переходов**

- В `stopped` интерфейс переходит только по ответу сервера, не по факту нажатия (FR-032).
- Показанный ход не продвигается без нового `closed` от сервера; обратного отсчёта и
  оценки времени окончания нет (FR-031).
- Ответ `idle` после показанного `running` отменяет прежний статус. Причина объясняется
  как возможная (перезапуск собирающего компонента), а не как установленный факт (FR-035).
- «Продолжить догон» — это новый запуск: закрытые сессии сервер исключает сам, интерфейс
  их не перечисляет (FR-025).
- Завершение прогона не меняет сводку: она перечитывается отдельным чтением (FR-037).

## 3. Запрос запуска (`LaunchRequest`) — состояние только в интерфейсе

Живёт до ответа сервера и после него — как контекст показа сужения. Серверным полем не
является (FR-040).

| Поле | Правила |
|---|---|
| `groups[]` | Выбор из пяти известных групп; по умолчанию все. Произвольный ввод невозможен (FR-021) |
| `whole_window` | По умолчанию включено: диапазон не передаётся, сервер берёт всё окно |
| `date_from` / `date_till` | Формат `ДД.ММ.ГГГГ`. Предзаполняются из `catchup_window`, редактируются при выключенном `whole_window` |
| `requested_from` / `requested_till` | Что человек ввёл. Сохраняется для показа рядом с принятым диапазоном при `clamped = true` |

**Валидация до отправки**

| Условие | Поведение |
|---|---|
| Дата не разбирается | Ошибка привязана к полю, значение сохранено, повтор доступен после исправления (FR-041) |
| Начало позже конца | Форма не отправляется, фокус переходит к началу диапазона |
| Ни одна группа не выбрана | Отправка невозможна: пустой выбор означал бы «все», а это уже делает флажок «Все группы» |

## 4. Раздел приложения

| Раздел | Адрес | Что читает |
|---|---|---|
| Портфель | `/` | Состояние портфеля (фича 001) |
| Рыночные данные | `/market-data` | Сводку полноты и состояние прогона |

Состояние прогона принадлежит оболочке, а не разделу: баннер процесса виден в обоих
разделах, пока прогон активен, и опрос переживает переход между ними (FR-006, research.md
R5).
