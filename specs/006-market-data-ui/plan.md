# Implementation Plan: Интерфейс рыночных данных и общая навигация

**Branch**: `feature/market-data-ui` | **Date**: 2026-09-10 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/006-market-data-ui/spec.md`

## Summary

Сводка полноты и управление догоном существуют с фичи 005, но доступны только из
терминала. Фича доводит их до человека: раздел «Рыночные данные» в интерфейсе, общая
оболочка с двумя разделами и общий баннер идущего процесса — и публичные маршруты
`backend-api`, без которых интерфейсу не с чем разговаривать.

Три части работы:

1. **`backend-api`** получает `/api/market-data/coverage` и `/api/market-data/catchup`
   (чтение, запуск, остановка) и передаёт их внутреннему каналу worker тем же способом,
   каким уже передаёт `POST /api/portfolio/refresh`. Публичной границей остаётся `/api`,
   worker наружу не выходит (FR-046).
2. **`backend-worker`** дополняет контракт фичи 005 тремя полями, без которых требования
   интерфейса невыполнимы: признак «покрыто, но пусто», границы окна догона и причина
   прерывания в пригодном для показа виде (см. [research.md](./research.md), R2).
3. **`frontend`** получает оболочку с маршрутами и навигацией, раздел рыночных данных со
   сводкой и управлением догоном и общий баннер процесса. Разметка и стили переносятся из
   артефакта Open Design, поведение — из `market-data-design.md`.

## Technical Context

**Language/Version**: Python 3.12 (backend), TypeScript 5.7 / React 19 (frontend)

**Primary Dependencies**: FastAPI, SQLAlchemy, httpx, Pydantic; React 19,
`@tanstack/react-query` 5, `@tanstack/react-table` 8, zod, Vite 6. Новых зависимостей
фича не вводит — маршрутизация делается своим модулем (research.md, R3).

**Storage**: PostgreSQL 17. **Миграций фича не добавляет**: новых данных не появляется,
читается уже собранное.

**Testing**: pytest + respx (контракт и интеграция), vitest + msw + Testing Library
(фронтенд)

**Target Platform**: контейнеры docker compose; браузеры с поддержкой ES2022, деградация
без View Transitions API

**Project Type**: веб-приложение — `backend/` (два контейнера из одного пакета) и
`frontend/`

**Performance Goals**: опрос состояния прогона раз в 3 секунды, пока прогон активен, и
полное молчание, когда неактивен (research.md, R5); сводка читается по входу в раздел и по
явному действию

**Constraints**: интерфейс обращается только к `/api`; `backend-api` не ходит во внешние
источники и не получает брокерский токен; окно сбора имеет ровно одного владельца —
worker; ширина от 360 px без горизонтальной прокрутки

**Scale/Scope**: 2 раздела, 5 групп данных, 6 состояний прогона, 10 пограничных случаев,
4 публичных маршрута

| IV. Обязательные проверки качества | Новые маршруты покрываются контрактными тестами, состояния экрана — тестами фронтенда; готовность проверяется одной командой `scripts/check.sh` целиком |

| VI. Изоляция по веткам | Работа в `feature/market-data-ui` |
| VII. Безопасность и конфигурация | Секретов фича не вводит. `backend-api` брокерский токен не получает и внешних источников не знает (FR-047a). Причина прерывания очищается от технических подробностей до выхода наружу (R2.3) — это же и требование FR-043 |
| VIII. Дизайн-инструмент как источник истины | Разметка, имена классов и стили переносятся из `market-data.html`, `financial-ai-shell.css`, `market-data.css` и структуры, которую строит `market-data.js`. Единственное отступление — способ запуска перехода между разделами (R4), зафиксировано с причиной |
| IX. Актуальность проектной документации | Фича меняет состав публичных маршрутов и добавляет раздел интерфейса, поэтому `README.md` и `AGENTS.md` актуализируются до объявления работы завершённой |
