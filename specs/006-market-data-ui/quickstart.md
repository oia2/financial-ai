# Quickstart: проверка интерфейса рыночных данных

Готовность изменения проверяется командой `scripts/check.sh` целиком. Этот документ о
другом: он показывает, что человек действительно может увидеть полноту данных и провести
догон, не открывая терминал.

## Предпосылки

```bash
cd deployments/docker-compose
docker compose up -d
```

Интерфейс — `http://localhost:8080` (или `FRONTEND_PORT` из `.env`). В хранилище должны
быть данные хотя бы за несколько сессий: на пустой базе догон намеренно недоступен, и это
отдельный проверяемый сценарий (С8).

Состояние хранилища при необходимости смотрится командой, существующей с фичи 005:

```bash
docker compose exec backend-worker python -m financial_ai.market_data.cli coverage
```

Числа этой команды и числа на экране должны совпадать — это и есть проверка С1.

## Публичная граница

### С0. Интерфейс знает только `/api`

**Что делаем**: открываем раздел «Рыночные данные» и смотрим сетевые запросы страницы.
Затем пробуем обратиться к внутреннему каналу снаружи:

```bash
curl -s http://localhost:8080/internal/catchup | head -c 60
docker compose ps --format '{{.Service}}\t{{.Ports}}'
```

**Ожидаем**: все запросы страницы идут в `/api/market-data/*`.

Обращение к `/internal/*` **не доходит до сборщика**: nginx отдаёт на этот путь страницу
приложения — сработал SPA-fallback `try_files … /index.html`. Смотреть надо на тело
ответа, а не на код: код будет `200`, и по нему одному легко сделать обратный вывод.
Второе подтверждение — у `backend-worker` нет опубликованных портов.

**Покрывает**: FR-046, FR-047, SC-011.

## Полнота данных

### С1. Сводка на экране совпадает с хранилищем

**Что делаем**: открываем раздел и сверяем каждую группу с выводом `cli coverage`.

**Ожидаем**: пять групп; покрытие, доля значений, границы периода и число непокрытых
сессий совпадают. Конкретных значений наблюдений на экране нет.

**Покрывает**: FR-008, FR-009, FR-013, SC-001.

### С2. Покрыто, но пусто — видно дважды

**Что делаем**: приводим группу в состояние, где сессии покрыты, а значений нет (на стенде
это состояние воспроизводится строками позиций, записанными до исправлений фичи 005).

**Ожидаем**: крупное уведомление над сводкой и выделенная строка группы. Покрытие не
окрашено как успех. Сказано, что догон сам по себе расхождения не исправит.

**Покрывает**: FR-010, FR-016, SC-002.

### С3. Группа без истории не выглядит недобранной

**Что делаем**: смотрим строку `reference` и открываем её сведения.

**Ожидаем**: числовых полей истории нет ни в строке, ни в панели; вместо них — объяснение
неприменимости. Нулей нет. Отсутствующие абсолютные числа строк показаны прочерком.

**Покрывает**: FR-014, FR-015.

## Управление догоном

### С4. Полный цикл без терминала

**Что делаем**: «Настроить запуск» → выбираем группы и диапазон → «Запустить» → наблюдаем
ход → «Остановить» → дожидаемся подтверждения → «Продолжить догон».

**Ожидаем**: на каждом шаге видны закрытые из запрошенных, оставшиеся, незакрывшиеся и
обрабатываемая сессия. Остановка выполняется одним действием без лишнего подтверждения.
Состояние «остановлен» появляется только после ответа сервера. Продолжение не собирает
заново уже закрытые сессии.

**Покрывает**: FR-019–FR-025, FR-028, FR-032, SC-003, SC-004.

### С5. Ход не выдумывается

**Что делаем**: во время прогона следим за индикатором между ответами сервера.

**Ожидаем**: подтверждённая длина не растёт без нового `closed`; обратного отсчёта и
оценки времени окончания нет; незакрывшиеся сессии показаны отдельным сегментом и в
закрытые не входят.

**Покрывает**: FR-029–FR-031, SC-007.

### С6. Прогон переживает переход и перезагрузку

**Что делаем**: во время прогона уходим в «Портфель», возвращаемся, затем перезагружаем
страницу.

**Ожидаем**: баннер процесса виден в обоих разделах; после перезагрузки состояние
восстановлено из ответа сервера, а не из памяти браузера.

**Покрывает**: FR-006, FR-035, FR-036, SC-005.

### С7. Перезапуск сборщика отменяет показанное «идёт»

**Что делаем**: во время прогона перезапускаем сборщик:

```bash
docker compose restart backend-worker
```

**Ожидаем**: экран переходит в «не запущен»; причина объяснена как возможная, а не как
установленный факт перезапуска; сводка показывает реальное состояние хранилища.

**Покрывает**: FR-035, SC-006.

## Отказы и пограничные состояния

### С8. Пустое хранилище

**Что делаем**: открываем раздел на базе без наблюдений.

**Ожидаем**: объяснение про первичную загрузку и обращение к администратору; запуск догона
недоступен; сообщения об аварии нет.

**Покрывает**: FR-026, FR-038.

### С9. Догонять нечего

**Что делаем**: открываем раздел, когда пропущенных сессий нет.

**Ожидаем**: спокойное подтверждение полноты; новый прогон не предлагается; доля строк со
значениями остаётся отдельным показателем.

**Покрывает**: FR-038.

### С10. Повторный запуск при идущем прогоне

**Что делаем**: во время прогона запускаем догон второй раз — из второй вкладки.

**Ожидаем**: отказ с причиной; счётчики и текущая сессия идущего прогона на экране
сохраняются.

**Покрывает**: FR-039.

### С11. Диапазон сужен сервером

**Что делаем**: запускаем догон с диапазоном заведомо шире окна.

**Ожидаем**: рядом показаны введённый и фактически принятый диапазоны; сообщение не
исчезает по таймеру.

**Покрывает**: FR-040.

### С12. Ошибки ввода дат

**Что делаем**: вводим неразбираемую дату, затем начало позже конца.

**Ожидаем**: ошибка привязана к полю, введённое значение сохранено, форма не отправляется,
фокус переходит к началу диапазона; после исправления запуск доступен.

**Покрывает**: FR-041.

### С13. Сборщик недоступен

**Что делаем**: останавливаем сборщик и открываем раздел:

```bash
docker compose stop backend-worker
```

**Ожидаем**: сообщение об отсутствии связи со сборщиком, отличное от отказа операции;
показанные ранее значения помечены как последние известные и не выдаются за подтверждённый
идущий процесс; технических подробностей и внутренних адресов в сообщении нет.

**Покрывает**: FR-036, FR-042, FR-043, FR-047b.

## Доступность и адаптивность

### С14. Клавиатура и фокус

**Что делаем**: открываем панель запуска и панель сведений о группе, закрываем их Escape.

**Ожидаем**: фокус возвращается к вызвавшей кнопке; вся форма проходится с клавиатуры;
элементы управления не ниже 44 px.

**Покрывает**: FR-053, FR-054, SC-010.

### С15. Узкий экран и отключённое движение

**Что делаем**: сужаем окно до 360 px; включаем системное предпочтение уменьшенного
движения.

**Ожидаем**: таблица перестроена в строки, горизонтальной прокрутки нет; анимации
отключены, смысл состояний сохранён.

**Покрывает**: FR-055, FR-056, SC-009.

## Что проверено на стенде 2026-09-10

Прогон через публичную границу, без обращения к внутреннему каналу:

| Сценарий | Результат |
|---|---|
| С0 | `/internal/*` снаружи отдаёт страницу приложения; у `backend-worker` портов нет |
| С1 | Сводка совпала с хранилищем: quotes 255/314, 81,21% покрытия при 96,09% строк со значениями |
| С3 | У `reference` полей окна в ответе нет вовсе |
| С4 | Полный цикл: запуск принят, `running` с текущей сессией, затем `finished`, closed 1 из 1 |
| С11 | Диапазон 01.09–03.09 сервер сузил до 01.09–01.09, `clamped: true` |
| С12 | `invalid_range` на «начало позже конца» |
| С10 | `unknown_group` на несуществующую группу |
| — | Остановка при неактивном прогоне возвращает `idle`, а не ошибку |
| FR-037 | После `finished` сводка перечитана отдельно: 255 → 256 из 314 |

Догон запускался **узко**: одна группа и один день, чтобы не гнать сотни обращений к
бесплатному публичному источнику ради проверки.

Сценарии, требующие браузера (С5, С6, С14, С15) и остановки сборщика (С7, С13), покрыты
тестами интерфейса; на живом стенде глазами они не проверялись.

являются.
