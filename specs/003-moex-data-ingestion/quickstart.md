# Quickstart: Сбор рыночных данных MOEX

Как поднять сбор данных локально и проверить, что цепочка `биржа → БД → набор →
ранжирование` действительно работает. Документ — руководство по запуску и проверке;
контракт запроса — в [contracts/daily-ml-request.md](./contracts/daily-ml-request.md),
перечень источников — в [contracts/moex-sources.md](./contracts/moex-sources.md), схема
хранения — в [data-model.md](./data-model.md).

---

## Предпосылки

| Что | Зачем |
|---|---|
| Docker + Docker Compose | стенд целиком |
| Python 3.12, `uv` | локальный запуск backend и тесты |
| Доступ к `iss.moex.com` | данные MOEX ISS публичны, токен **не** нужен |

Секретов для сбора рыночных данных не требуется. Токен брокера остаётся у
`backend-worker` для синхронизации счёта и к новому коду отношения не имеет.

---

## 1. Конфигурация

```bash
cp deployments/docker-compose/.env.example deployments/docker-compose/.env
```

Настройки сбора (значения по умолчанию рабочие):

```env
MARKET_DATA_ENABLED=true
MARKET_DATA_INGEST_AFTER_CLOSE=19:30      # время запуска после закрытия, Europe/Moscow
MARKET_DATA_BACKFILL_FROM=                # пусто — вся доступная история
MARKET_DATA_PRICE_WINDOW_SESSIONS=314
MARKET_DATA_GLOBAL_WINDOW_SESSIONS=314
MARKET_DATA_POSITIONS_WINDOW_SESSIONS=82
MARKET_DATA_DATASET_RETENTION_DAYS=30
DAILY_ML_URL=http://daily-ml-emulator:8000
```

Глубины окон не выдуманы: выведены из конфигурации признаков модели, см.
[research.md §1](./research.md). Для стенда их можно уменьшить — сбор пойдёт быстрее.

---

## 2. Запуск

```bash
docker compose -f deployments/docker-compose/docker-compose.yml up --build
```

Миграции применяются при старте `backend-api`. Проверка живости:

```bash
curl -s localhost:8080/api/health
curl -s localhost:8100/health
```

---

## 3. Первичная загрузка истории

Разовая и долгая. Для стенда разумно ограничить глубину:

```bash
docker compose -f deployments/docker-compose/docker-compose.yml exec backend-worker \
  python -m financial_ai.market_data.cli backfill --from 2025-01-01
```

Прерывание не страшно: повторный запуск продолжает с места остановки.

## Проверочные сценарии

Соответствуют критериям приёмки из [spec.md](./spec.md). Выполняются командами выше.

### С1. Календарь заполнен и гейтит даты (FR-003, SC-003)

```bash
docker compose … exec backend-worker \
  python -m financial_ai.market_data.cli calendar --show-last 10
```

Ожидается список последних торговых сессий. Выходных и праздников в нём быть не должно.

### С2. Сбор за сессию наполняет хранилище (US1 AS1, SC-001)

```bash
docker compose … exec backend-worker \
  python -m financial_ai.market_data.cli run --session 2026-08-28
```

Ожидается: по каждому источнику зафиксирован исход, число записанных наблюдений
ненулевое для котировок.

### С3. Повторный сбор ничего не дублирует (US1 AS2, SC-002)

Выполнить С2 дважды и сравнить количество наблюдений до и после:

```bash
docker compose … exec backend-worker \
  python -m financial_ai.market_data.cli stats --session 2026-08-28
```

Ожидается: одинаковое число в обоих прогонах.

### С4. В неторговый день к бирже не ходим (US1 AS3, FR-003)

Запустить сбор на заведомо выходную дату:

```bash
docker compose … exec backend-worker \
  python -m financial_ai.market_data.cli run --session 2026-01-04
```

Ожидается: исход `skipped`, обращений к бирже нет.

### С5. Недоступность биржи не портит данные (US1 AS4, SC-008)

Запустить сбор при отключённой сети контейнера и убедиться, что прогон помечен
неуспешным с причиной, а количество ранее собранных наблюдений не изменилось.

### С6. Точность цен сохранена (FR-012, SC-004)

Проверяется автотестами: значение биржи и сохранённое совпадают до последнего знака,
`float` на пути не используется.

```bash
cd backend && uv run pytest tests/market_data/test_precision.py -q
```

Ожидается: все тесты проходят. Отдельной команды для этого нет намеренно — проверка
должна выполняться на каждом прогоне гейта, а не по требованию.

### С7. Набор материализуется и опознаётся дайджестом (FR-016, FR-017)

```bash
docker compose … exec backend-worker \
  python -m financial_ai.ranking.cli build --asof 2026-08-28
```

Ожидается: ссылка на набор и дайджест. Повторный запуск при неизменных данных даёт **тот
же дайджест**.

### С8. Запрос ранжирования проходит целиком (US2, SC-005, SC-006)

```bash
docker compose … exec backend-worker \
  python -m financial_ai.ranking.cli rank --asof 2026-08-28
```

Ожидается ответ с ранжированием, где:

- `input_digest` совпадает с дайджестом из С7;
- активов в `items` не больше, чем передано;
- каждый переданный актив либо в `items`, либо в `excluded` с причиной.

### С9. Тот же вход даёт тот же ответ (SC-006)

Выполнить С8 дважды и сравнить `items`. Ожидается совпадение; отличаться может только
`generated_at`.

### С10. Звено ранжирования без секретов и без БД (FR-022, SC-007)

```bash
docker compose … exec daily-ml-emulator printenv \
  | grep -iE "TBANK|DATABASE|TOKEN|PASSWORD" && echo "НАЙДЕНО — ПРОВАЛ" || echo "секретов нет — OK"
```

### С11. Сбой ранжирования отличим от сбоя сбора (US2 AS4, FR-025)

Остановить контейнер ранжирования и выполнить С8. Ожидается: ошибка помечена как сбой
ранжирования, собранные данные на месте, повторный С8 после подъёма контейнера проходит.

## Локальная разработка

```bash
cd backend
uv sync
uv run python -m financial_ai.market_data.cli run --session 2026-08-28
```

## Проверки качества

```bash
scripts/check.sh                # полный гейт, включая сборку образов
scripts/check.sh --no-docker    # быстрый цикл, НЕ полный гейт
```

Тесты обращений к бирже используют подменённые ответы: сеть для прогона тестов не нужна.

## Что реализовано на сегодня

Собираются восемь источников: торговый календарь, дневные котировки, агрегаты торгов,
глобальные ряды (IMOEX, RTSI, RGBI, RVI, курс USD), отраслевая принадлежность, дневной
состав индексов, макроряды Банка России и позиции по фьючерсам.

В набор входных данных попадают цены, глобальные ряды и позиции — каждое со своим окном
(314 сессий для цен и глобальных рядов, 82 для позиций).

Сценарии С1–С11 выполнимы на полном составе источников.

**Два источника не перенесены**, оба с причиной:

| Источник | Почему |
|---|---|
| Brent | Требует не переноса парсера, а построения производного ряда: 721 строка с определением срока контракта, таблицей контрактов и оценкой правила переката. Плюс зависимость от pandas |
| Дивиденды | Источник — брокер, и токен у worker уже есть, а SDK умеет `GetDividends`. Но запрос требует `figi` или `instrument_id`, а собранные данные ключуются по `asset_id`. Сопоставление `asset_id` ↔ FIGI явно вынесено за объём и этой фичи, и фичи 002 |

**Разбор страниц Банка России проверен структурно, но не на живом источнике.** Селекторы
и форматы перенесены из исходного кода дословно, тесты подтверждают перенос на образце
ожидаемой структуры. Сверка с настоящей страницей `cbr.ru` требует доступа к сети:

```bash
cd backend && uv run python -m financial_ai.market_data.cli verify-cbr --session 2026-08-28
```

Команда обращается к ЦБ по-настоящему и показывает разобранные значения. Если вёрстка
изменится, разбор откажет с сообщением, а не вернёт молча пустой результат — но выполнить
проверку перед боевым запуском всё равно следует.

Перечень перенесённого с указанием происхождения — в
`backend/src/financial_ai/market_data/PROVENANCE.md`.
