# Contract: запрос ранжирования к звену Daily ML

**База**: `http://daily-ml-emulator:8000` внутри сети развёртывания

**Аутентификация**: нет. Звену ранжирования не нужны ни секреты, ни доступ к БД

Этот контракт заменяет прежний `GET /rankings?decision_date=…` из фичи 002. Он же —
будущий контракт обученной модели: контейнер с ней встанет на место эмулятора.

> Пока на этом адресе работает эмулятор, все скоры вымышлены. Успешный ответ содержит
> `emulated: true`, и потребитель обязан это проверять.

---

## `POST /rankings`

Возвращает ранжирование активов на дату решения.

### Тело запроса

```json
{
  "asof_date": "2026-08-28",
  "dataset": {
    "ref": "file:///datasets/20260828T183000Z-3aab1480aa97",
    "digest": "sha256:9f2c…",
    "windows": {
      "price_sessions": 314,
      "aggregate_sessions": 314,
      "global_sessions": 314,
      "positions_sessions": 82
    }
  },
  "assets": [
    { "asset_id": "EQ_AST_SBER", "price_series_id": "EQ_PRS_SBER" },
    { "asset_id": "EQ_AST_GAZP", "price_series_id": "EQ_PRS_GAZP" }
  ]
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `asof_date` | date `YYYY-MM-DD` | Дата решения — последняя завершённая торговая сессия |
| `dataset.ref` | string | Ссылка на неизменяемый набор входных данных |
| `dataset.digest` | string | Дайджест содержимого набора |
| `dataset.windows` | object | Фактические глубины окон, вошедшие в набор |
| `assets[]` | array | Активы, данные которых вошли в набор |

### Что лежит в наборе по ссылке

Состав выведен из входов модели, объявленных в `pipelines/data_plane_step0/pipeline.py:88-103`
исследовательского репозитория.

| Файл | Содержимое | Ось |
|---|---|---|
| `prices.json` | OHLCV по ценовым рядам | сессии × ряды |
| `aggregates.json` | `value`, `num_trades`, `waprice` | сессии × ряды |
| `global.json` | индексы, веса `IDX_WEIGHT_*`, USD, ставка, ЗКЦ, Brent | сессии × ряды |
| `positions.json` | позиции ФИЗ/ЮР по фьючерсам | сессии × активы |
| `sectors.json` | `asset_id → сектор` | оси сессий нет |
| `manifest.json` | дайджест, окна, сессии, активы | — |

Числа во всех файлах передаются **строками**, пропуск — `null`. Пропуск не заменяется
нулём: отсутствие данных и ноль — разные утверждения.

**Дивидендов в наборе нет** намеренно. Исследовательский репозиторий запрещает их как
ex-ante признак (`data_plane_step0/pipeline.py:1057`) и использует только при построении
меток. Обучение вне платформы, поэтому на инференс они не идут.

**Почему ссылка, а не ряды.** Окно в 314 сессий по 288 активам — около 5,9 МБ, из
которых новой является одна сессия из 314. Пересылать 99,7% уже известного при каждом
запросе бессмысленно. Ссылка с дайджестом даёт и экономию, и воспроизводимость: дайджест
**и есть** идентификатор входа.

**Кто решает, какие активы попадут в ранжирование.** Отправитель передаёт активы, данные
которых у него есть, и за модель ничего не решает. Допустимость определяет сторона
модели: это правило строится тем же конвейером, что и признаки, и живёт вместе с ним.

### `200 OK`

```json
{
  "asof_date": "2026-08-28",
  "model_id": "daily-ml-emulator-v1",
  "input_digest": "sha256:9f2c…",
  "generated_at": "2026-08-29T09:14:02Z",
  "emulated": true,
  "emulation_notice": "Значения вымышлены эмулятором Daily ML…",
  "included_asset_count": 2,
  "excluded": [],
  "items": [
    { "rank": 1, "asset_id": "EQ_AST_SBER", "price_series_id": "EQ_PRS_SBER", "score": "0.6667" },
    { "rank": 2, "asset_id": "EQ_AST_GAZP", "price_series_id": "EQ_PRS_GAZP", "score": "0.3333" }
  ]
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `asof_date` | date | Дата решения из запроса |
| `model_id` | string | Идентификатор модели, выдавшей ранжирование |
| `input_digest` | string | Дайджест набора из запроса, повторённый в ответе |
| `generated_at` | string, UTC | Момент формирования ответа |
| `emulated` | boolean | Признак эмуляции. Исчезнет при замене настоящей моделью |
| `emulation_notice` | string | Человекочитаемое предупреждение |
| `included_asset_count` | integer | Сколько активов вошло в ранжирование |
| `excluded` | array | Переданные, но не вошедшие активы с причиной |
| `items` | array | Позиции ранжирования, упорядоченные по возрастанию `rank` |
| `items[].rank` | integer | Место в порядке убывания скора; `1` — лучший |
| `items[].asset_id` | string | Экономический актив |
| `items[].price_series_id` | string | Ценовой ряд этого актива |
| `items[].score` | string | Кросс-секционный ранжирующий скор внутри даты |

### Инварианты

1. `items` не содержит активов, которых не было в запросе.
2. `rank` пробегает непрерывный ряд `1..N` без повторов; `items` отсортирован по нему.
3. `asset_id` уникален в пределах ответа.
4. `score` строго убывает по мере роста `rank` и передаётся **строкой**, не числом.
5. Каждый переданный актив либо присутствует в `items`, либо перечислен в `excluded` с
   причиной. Молчаливая пропажа актива недопустима.
6. `input_digest` в ответе равен `dataset.digest` из запроса.
7. Один и тот же дайджест при неизменном наборе даёт одно и то же ранжирование.

### Смысл `score`

Осмыслен **только порядок внутри одной даты решения**. Абсолютное значение интерпретации
не имеет, доходности не означает и сравнению между датами не подлежит. Это свойство
настоящей модели, обучаемой ранжирующей функцией потерь, а не упрощение эмулятора.

### Ошибки

Форма единая для всего проекта: `{"detail": {"code": "…", "message": "…"}}`.

| Код | Ситуация | `detail.code` |
|---|---|---|
| `422` | `asof_date` отсутствует или не разбирается как дата | `invalid_asof_date` |
| `422` | Не передан `dataset` или пустой `assets` | `invalid_request` |
| `422` | Дайджест не совпадает с содержимым набора | `dataset_digest_mismatch` |
| `404` | Набор по ссылке недоступен | `dataset_not_found` |
| `404` | Неизвестный путь | `error` |
| `405` | Неподдерживаемый метод | `error` |

Ранжирование при ошибке не выдаётся.

Эмулятор набор не читает, поэтому `dataset_digest_mismatch` и `dataset_not_found` он не
возвращает — они относятся к настоящей модели. Это единственное отличие в поведении, и
оно зафиксировано намеренно.

## Что переживёт замену эмулятора настоящей моделью

| Поле | Судьба |
|---|---|
| `asof_date`, `model_id`, `input_digest`, `generated_at` | **остаются** |
| `items[]` целиком, `included_asset_count`, `excluded[]` | **остаются** |
| `emulated`, `emulation_notice` | **исчезнут** — существуют только у эмулятора |

Потребителю: закладываться на **наличие** `emulated` в будущем не нужно, но **проверять**
его, пока он есть, обязательно — иначе вымышленные скоры однажды дойдут до решения о
сделке как настоящие.

## Что изменилось против контракта фичи 002

| Было | Стало | Почему |
|---|---|---|
| `GET` с единственным параметром `decision_date` | `POST` с датой, набором и активами | Модели нужны данные; их состав определяет отправитель, а не конфигурация эмулятора |
| Вселенная из конфигурации эмулятора | Активы приходят в запросе | Конфигурационный список не имеет отношения к тому, что торговалось |
| Допустимость не рассматривалась | Определяет сторона модели | Правило строится конвейером признаков и живёт вместе с ним |
| Идентификатора входа не было | `input_digest` в запросе и ответе | Без него нельзя доказать, на каких данных получено ранжирование |
