# Tasks: Сбор рыночных данных MOEX и передача их в Daily ML

**Input**: Design documents from `/specs/003-moex-data-ingestion/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md),
[data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Tests**: включены по Принципу IV конституции — новая существенная логика сопровождается
тестами, если её можно проверить автоматически. Здесь можно проверить почти всё:
идемпотентность сбора, гейт календаря, точность цен, детерминизм дайджеста, разделение
сбоев. Обращения к бирже в тестах подменяются через `respx`, сеть не нужна.

**Organization**: задачи сгруппированы по user story. Дополнительно действует порядок
срезов из [plan.md](./plan.md): срез A даёт замкнутую цепочку, срезы B и C добавляют
источники, не меняя границ.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: можно выполнять параллельно (разные файлы, нет незакрытых зависимостей)
- **[Story]**: к какой user story относится задача (US1…US5)
- В описании — точный путь к файлу

## Path Conventions

Структура задана в [plan.md](./plan.md): код внутри существующего пакета
`backend/src/financial_ai/` двумя подпакетами — `market_data/` и `ranking/`. Миграции —
`backend/migrations/`. Развёртывание — `deployments/docker-compose/`.

## Implementation Strategy

### MVP — срез A (Phases 1–5)

1. Setup и Foundational
2. US1 срез A: календарь и котировки собираются
3. US2: набор материализуется, запрос уходит
4. US3: эмулятор принимает контракт
5. **ОСТАНОВИТЬСЯ И ПРОВЕРИТЬ**: цепочка `биржа → БД → набор → ранжирование` работает целиком

На этом шаге фича уже даёт ценность: контракт будущей модели отработан на живых данных.

### Incremental Delivery

1. Срез A → замкнутая цепочка (**MVP**)
2. + US4 → систему можно развернуть с нуля
3. + срез B → глобальные ряды в наборе
4. + срез C → задержанные источники и маски
5. + US5 и Polish → документация актуальна, гейт пройден

### Parallel Team Strategy

После среза A работа хорошо делится: срез B и срез C трогают разные источники и разные
файлы. Общая точка — `ingest.py` и состав набора, их стоит объединять по очереди.
