# Contract: расчёт плана портфеля

План — утверждение о желаемом составе счёта, полученное применением правила распределения к
последнему успешному ранжированию и текущему состоянию портфеля.

**Расчёт не меняет портфель, не выставляет заявок и не обращается к брокеру.** Маршрутов
исполнения в этом контракте нет и не появится: в исследовательском репозитории исполнение —
отдельный модуль, принимающий готовое количество на вход.

Считает `backend-api`: все входы уже в хранилище, внешних обращений расчёт не делает.

---

## `GET /api/portfolio-plan/policies`

Правила распределения, перенесённые из исследования.

```json
{
  "policies": [
    {
      "id": "equal_top20",
      "title": "Равные доли · первые 20",
      "asset_count": 20,
      "description": "Первые 20 активов ранжирования, равными долями расчётного капитала.",
      "source": "handoff §10.1"
    },
    {
      "id": "rank_zones_100",
      "title": "По диапазонам рангов · первые 100",
      "asset_count": 100,
      "description": "Ранги 1–20: 24,03%; 21–30: 10,63%; 31–50: 20,39%; 51–100: 44,95%. Внутри диапазона — поровну.",
      "source": "handoff §10.3"
    }
  ],
  "default_policy": "equal_top20"
}
```

Перечень задаётся сервером: произвольное правило человеком не вводится.

## `POST /api/portfolio-plan`

```json
{
  "policy": "equal_top20",
  "capital_limit": "148397.00",
  "fee_percent": "0.04"
}
```

| Поле | Обязательно | Умолчание | Смысл |
|---|---|---|---|
| `policy` | да | — | Идентификатор правила |
| `capital_limit` | нет | весь расчётный капитал | Верхняя граница распределяемого, ₽ |
| `fee_percent` | нет | `0.04` | Комиссия за **одну** сторону, % |

Умолчание комиссии — половина round-trip издержек `0,0008` из диагностики исследования.

### `200 OK`

```json
{
  "asof_date": "2026-09-11",
  "run_id": 143,
  "policy": "equal_top20",
  "policy_title": "Равные доли · первые 20",
  "emulated": true,
  "price_source": { "kind": "session_close", "session_date": "2026-09-11" },
  "capital": {
    "eligible": "148397.000000000",
    "limit": "148397.000000000",
    "allocated": "141230.000000000",
    "cash_after": "7167.000000000",
    "fee_total": "56.49",
    "account_total": "360797.000000000"
  },
  "positions": [
    {
      "asset_id": "EQ_AST_SBER",
      "ticker": "SBER",
      "name": "Сбербанк",
      "rank": 4,
      "target_weight": "0.05",
      "weight_after": "0.017462",
      "price": "315.00",
      "lot_size": 10,
      "target_lots": 2,
      "target_quantity": "20",
      "target_value": "6300.000000000",
      "current_quantity": "100",
      "delta_quantity": "-80",
      "delta_value": "-25200.000000000"
    }
  ],
  "untouched": [
    {
      "ticker": "SU26238RMFS4",
      "name": "ОФЗ 26238",
      "quantity": "200",
      "value": "212400.000000000",
      "weight_after": "0.588693",
      "reason": "вне вселенной модели"
    }
  ],
  "excluded": [
    { "asset_id": "EQ_AST_XXXX", "rank": 17, "reason": "не известен размер лота" }
  ]
}
```

| Правило | Почему |
|---|---|
| Все денежные величины — строки | `float` на пути «БД → API → JSON» теряет копейки |
| Количества — тоже строки | Количество приходит от брокера как `Decimal` и так же отдаётся разделом «Портфель». Второе представление того же числа в соседнем разделе рано или поздно разойдётся с первым |
| Числа лотов и размер лота — целые | Это счётные величины, а не суммы: дробного лота не существует |
| `price_source` присутствует всегда | Цена — закрытие названной сессии, а не текущая котировка, и принять одно за другое нельзя |
| `target_quantity` кратно `lot_size` | На бирже торгуют лотами; дробное количество неисполнимо |
| Остаток округления — в `cash_after` | Между активами он не перераспределяется: иначе доли исказятся относительно правила |
| `untouched` присутствует всегда | Облигации и денежный фонд планом не затрагиваются, и это утверждение, а не умолчание |
| `excluded` присутствует всегда | Актив, выпавший из плана, должен быть назван с причиной, а не исчезнуть |
| `emulated` | Ранжирование получено эмулятором: план построен на вымышленных скорах, и сказать об этом обязан тот, кто план отдаёт |
| `policy_title` | Название правила рядом с идентификатором. `equal_top20` — ключ для машины; человеку на экране нужно «Равные доли · первые 20» |
| `positions` упорядочены от продаж к покупкам | Покупки оплачиваются выручкой от продаж. Список, начинающийся с покупок, читается как руководство к действию, которое невыполнимо: денег на них ещё нет |
| У `untouched` есть `value` | Доля позиции считается от всего счёта. Без стоимости облигаций доля акций вышла бы больше настоящей |
| `weight_after` и `account_total` считает сервер | Доля позиции после плана — деление денежных величин. В браузере оно означало бы разбор строк в `float`, а это ровно то, что на этом пути запрещено |
| Комиссия считается по обороту плана и **не резервируется** из лимита | Оборот известен только после распределения, и резерв «на глаз» сместил бы веса относительно правила. Величина показывается отдельной строкой |

### Отказы

| Код | `code` | Когда |
|---|---|---|
| `409` | `no_successful_ranking` | Успешного прогона нет |
| `409` | `ranking_stale` | Вход последнего прогона изменился: решение относится к другим данным |
| `409` | `broker_not_connected` | Неизвестны деньги и позиции |
| `409` | `portfolio_stale` | Снимок счёта устарел |
| `422` | `insufficient_assets` | В выдаче меньше активов, чем требует правило; названы требуемое и доступное |
| `422` | `unknown_policy` | Правила с таким идентификатором нет |
| `422` | `invalid_limit`, `invalid_fee` | Значение не разбирается или вне допустимого |

Отказ — это отсутствие плана, а не пустой план: показать пустой состав значило бы сказать
«продай всё».
