# Quickstart: проверка жизненного цикла Daily ML и плана портфеля

Готовность изменения проверяется командой `scripts/check.sh` целиком. Этот документ о
другом: он показывает, что цикл действительно замкнулся и работает без ручного управления.

## Предпосылки

```bash
cd deployments/docker-compose
docker compose up -d
```

Интерфейс — `http://localhost:8080`. В хранилище должны быть собранные данные хотя бы за
часть окна.

Состояние данных смотрится существующей командой:

```bash
docker compose exec backend-worker python -m financial_ai.market_data.cli coverage
```

---

## Данные

### С1. Граница данных доводится до последней закрытой сессии

**Что делаем**: останавливаем сборщик на несколько торговых дней, затем запускаем.

**Ожидаем**: календарь синхронизирован, пропущенные сессии собраны, граница данных
совпадает с последней **закрытой** сессией. Текущая незакрытая сессия не собрана.

**Покрывает**: FR-006–FR-008, SC-001.

### С2. Разрыв догоняется целиком, а заданный предел его останавливает

**Что делаем**: два прогона. Первый — при умолчании (`MARKET_DATA_STARTUP_RECOVERY_MAX_SESSIONS=0`):
приводим систему к разрыву в несколько сессий и запускаем. Второй — задаём предел числом
меньше разрыва и запускаем снова.

**Ожидаем**: в первом прогоне собираются все пропущенные сессии в границах окна догона, и
ранжирование получает одно задание — за последнюю готовую дату, а не за каждую. Во втором
автоматический сбор не выполняется вовсе, разрыв показан в интерфейсе, предложено
воспользоваться управляемым догоном.

**Покрывает**: FR-009, FR-029.

### С3. Планировщик не повторяет сделанное

**Что делаем**: после успешного сбора перезапускаем сборщик в тот же день.

**Ожидаем**: повторного сбора той же сессии не происходит. Обращений к бирже нет.

**Покрывает**: FR-030, FR-031, SC-002.

### С4. Неудачная попытка не блокирует повтор

**Что делаем**: доводим сбор до отказа, затем восстанавливаем доступность источника.

**Ожидаем**: следующая проверка пробует снова в тот же день.

**Покрывает**: FR-032.

### С5. Размер лота собран

```bash
docker compose exec backend-worker python -m financial_ai.market_data.cli coverage
```

**Ожидаем**: у справочника появились размеры лотов; отсутствие лота у отдельного актива не
делает дату неготовой.

**Покрывает**: FR-005a, FR-065.

## Жизненный цикл

### С6. Ранжирование считается само

**Что делаем**: дожидаемся сбора за закрытую сессию.

**Ожидаем**: прогон создан без участия человека, прошёл состояния «ожидает» → «выполняется»
→ «завершён», результат сохранён, последняя успешная дата обновилась.

**Покрывает**: FR-012, FR-016, SC-001.

### С7. Состояния наблюдаемы

**Что делаем**: смотрим раздел «Ранжирование» во время работы.

**Ожидаем**: видны обрабатываемая дата, время начала и длительность. Задержка эмулятора
позволяет застать состояние «выполняется».

**Покрывает**: FR-042.

### С8. Повторно то же не считается

**Что делаем**: нажимаем «проверить сейчас» при актуальном состоянии; затем перезапускаем
сборщик и повторяем.

**Ожидаем**: ноль заданий, ноль обращений к модели, ответ «всё актуально».

**Покрывает**: FR-019, FR-022, SC-006.

### С9. Прерванный прогон не зависает

**Что делаем**: перезапускаем сборщик во время выполнения прогона:

```bash
docker compose restart backend-worker
```

**Ожидаем**: прогон помечен прерванным и поставлен в очередь заново; в состоянии
«выполняется» не остался.

**Покрывает**: FR-027, SC-005.

### С10. Неполный вход останавливает модель

**Что делаем**: создаём пропуск внутри требуемого окна обязательной группы.

**Ожидаем**: дата не считается готовой, ранжирование не запускается, интерфейс объясняет,
чего не хватает.

**Покрывает**: FR-003, SC-003.

### С11. Догон не порождает лавину заданий

**Что делаем**: закрываем управляемым догоном исторический пропуск.

**Ожидаем**: создан **не более одного** нового задания — за последнюю готовую дату.
Исторические даты заданиями не становятся.

**Покрывает**: FR-024, FR-035, SC-004.

### С12. Отказ звена не портит данные

**Что делаем**: останавливаем эмулятор и дожидаемся попытки.

```bash
docker compose stop daily-ml-emulator
```

**Ожидаем**: прогон в состоянии отказа с понятной причиной; собранные данные не изменились;
доступен повтор.

**Покрывает**: FR-037, FR-038, FR-039.

### С13. Повтор недоступен без набора

**Что делаем**: открываем прогон, входной набор которого удалён ретеншеном.

**Ожидаем**: результат виден, повтор недоступен, причина объяснена.

**Покрывает**: FR-040.

### С14. Пауза останавливает запуски, но не сбор

**Что делаем**: ставим автоматический режим на паузу и дожидаемся закрытия сессии.

**Ожидаем**: данные собраны, ранжирование не запущено, интерфейс говорит, что сбор
продолжается.

**Покрывает**: FR-036, FR-055.

## План портфеля

### С15. План считается и воспроизводим

**Что делаем**: открываем раздел, выбираем правило, считаем план; повторяем с теми же
параметрами.

**Ожидаем**: состав соответствует порядку ранжирования, веса — правилу, результат при
повторе тот же.

**Покрывает**: FR-057, FR-058, SC-010.

### С16. Количества выражены лотами

**Ожидаем**: каждое количество кратно размеру лота; остаток округления остался деньгами и
между активами не перераспределён.

**Покрывает**: FR-066, FR-067.

### С17. Вне вселенной модели не трогается

**Ожидаем**: облигации и денежный фонд перенесены без изменений и в расчётный капитал не
вошли.

**Покрывает**: FR-060.

### С18. План не строится на плохом входе

**Что делаем**: по очереди — нет успешного ранжирования, ранжирование устарело, счёт не
подключён.

**Ожидаем**: в каждом случае плана нет и сказано, чего дождаться. Пустой состав не
показывается.

**Покрывает**: FR-061.

### С19. Цена подписана датой

**Ожидаем**: рядом с ценами указано, что это закрытие названной торговой сессии.

**Покрывает**: FR-065.

### С20. Ничего не исполняется

**Что делаем**: проходим оба раздела целиком.

**Ожидаем**: ни одного действия, меняющего портфель или выставляющего заявку. Запросов к
брокеру на запись нет.

**Покрывает**: FR-063, FR-071, SC-011.

## Границы и дизайн

### С21. Внутренний канал недоступен снаружи

```bash
curl -s http://localhost:8080/internal/daily-ml | head -c 60
docker compose ps --format '{{.Service}}\t{{.Ports}}'
```

**Ожидаем**: на `/internal/*` приходит страница приложения (SPA-fallback), а не ответ
сборщика; у `backend-worker` нет опубликованных портов. Смотреть надо на тело ответа: код
будет `200`.

**Покрывает**: FR-070.

### С22. Соответствие артефакту

**Что делаем**: сверяем состав и имена элементов по
[contracts/ui-states.md](./contracts/ui-states.md) — **по `data-od-id`**, а не по классам.

**Ожидаем**: расхождений нет, кроме зафиксированных с причиной.

**Покрывает**: FR-072, SC-009.

## Что показал прогон на живом стенде (2026-09-12)

Сценарии пройдены на поднятом стенде с настоящими данными MOEX и настоящим эмулятором.
Цикл замкнулся: набор за 2026-09-03 материализован (314 сессий, 512 активов), прогон
создан и выполнен, 512 позиций ранжирования сохранены, дата успешного ранжирования
продвинулась. Повторная проверка вернула `already_up_to_date` и **не** создала второго
задания (С6, С7, С8). Пауза остановила создание заданий, сбор данных при этом продолжался
(С14). Внутренний канал снаружи недоступен: на `/internal/*` приходит страница приложения,
портов у `backend-worker` нет (С21). Лоты собраны с биржи — 505 бумаг, `GAZP` 10, `SBER` 1
(С5). План посчитан на настоящем портфеле: количества кратны лоту, цена подписана сессией
закрытия, действий исполнения в границе нет (С15–С20).

Прогон нашёл **четыре дефекта**, которых не увидели ни тесты, ни сборка. Каждый исправлен,
и на каждый добавлена проверка:

| Что | Почему не поймали раньше | Исправление |
|---|---|---|
| Сбой восстановления при старте уносил **весь** worker: первый тик не был защищён, и `PermissionError` на томе наборов останавливал контейнер вместе со сбором данных и синхронизацией счёта | Цикл планировщика защищён, а **стартовый** тик — нет. В тестах этот путь не падал | Стартовый тик обёрнут: ранжирование — одна из работ worker'а, а не условие его существования. Ошибки записи набора приводятся к `DatasetError` |
| Именованный том `/datasets` создавался root'ом, а worker работает под `app`: набор не записывался | Каталога нет в образе, и Docker создавал его владельцем по умолчанию. Ни тесты, ни сборка образов этого не проверяют | Каталог создаётся в образе и принадлежит `app` |
| Готовность данных считалась **дважды**: в worker'е и в `backend-api`, по разным конфигурациям. Раздел показывал «готовых данных нет» рядом с успешным прогоном ровно за эту дату | Контрактные тесты подделывали worker и потому расхождения не видели | Счёт ушёл в worker (`GET /internal/daily-ml/state`), в ответ добавлен `readiness_known`: «нет готовой даты» и «готовность неизвестна» — разные утверждения |
| Команды «проверить» и «повторить» ждали окончания инференса и не укладывались в таймаут: команда выполнялась, а вызывающий получал «сборщик недоступен» | У эмулятора инференс занимает секунды, и в тестах это не проявлялось | Обработка очереди вынесена в фон; ответ говорит о том, что уже произошло |
| Акции вне выборки правила попадали в «вне вселенной модели» наравне с ОФЗ: не входили в расчётный капитал и молча оставались в портфеле (на стенде — `LKOH`, `NVTK`, `GMKN`, `T`, `YDEX`) | В тестах ранжирование состояло ровно из двадцати активов — столько же, сколько берёт правило | Вселенная — **вся выдача модели**; позиции вне выборки закрываются, а не игнорируются. Расчётный капитал на стенде вырос с 42 107 ₽ до 381 980 ₽ |

Прерванный прогон проверен вживую (С9): перезапуск во время выполнения снял состояние
«выполняется», пометил прогон прерванным и вернул его в очередь — ровно то, что требует
спецификация. До исправления он оставался отказом и ждал человека.

Сценарии С1–С4, С10, С11 на этом стенде не воспроизводились: они требуют искусственного
разрыва рыночных данных, а восстановление такого разрыва стоит сотен обращений к бирже.
Их поведение закрыто тестами `backend/tests/market_data/` и `backend/tests/daily_ml/`.
