# Data Model: жизненный цикл Daily ML и план портфеля

Фича добавляет две таблицы и одну колонку. Всё остальное — вычисляемые величины поверх уже
существующих данных.

---

## 1. Прогон Daily ML (`daily_ml_run`)

Одно выполнение ранжирования за дату решения на конкретном входе и конкретной версии
модели. Это история принятых решений, поэтому она хранится — в отличие от состояния догона,
которое живёт в процессе намеренно.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | целое | Первичный ключ |
| `asof_date` | дата | Дата решения |
| `dataset_digest` | строка | Дайджест набора, на котором выполнен прогон |
| `dataset_ref` | строка | Ссылка на набор. Набор удаляется ретеншеном, ссылка остаётся |
| `model_id` | строка | Идентификатор модели |
| `model_version` | строка | Версия модели |
| `status` | строка | `queued`, `running`, `success`, `failed` |
| `attempt` | целое | Номер попытки, начиная с 1 |
| `created_at` | момент | Когда задание создано |
| `started_at` | момент \| null | Когда началось выполнение |
| `finished_at` | момент \| null | Когда завершилось |
| `error_code` | строка \| null | Машинный код отказа |
| `error_message` | текст \| null | Причина, пригодная для показа человеку |
| `included_asset_count` | целое \| null | Сколько активов в выдаче |
| `window_from`, `window_till` | дата \| null | Границы окна входа, ушедшего модели |
| `input_complete` | логическое \| null | Обязательный вход был объявлен полным |
| `emulated` | логическое \| null | Результат получен эмулятором, а не моделью |

**Ограничения**

- `UNIQUE (asof_date, dataset_digest, model_id, model_version)` — ключ идемпотентности.
  Атомарен по устройству: конкурентная вставка ловится конфликтом, а не проверкой
  «сначала посмотрим».
- Индекс по `asof_date DESC` — история показывается новыми сверху.
- Индекс по `status` — выборка очереди.

**Правила**

- Повторная попытка создаёт **новую строку** с тем же ключом? Нет: ключ тот же, значит
  строка та же. Повтор увеличивает `attempt`, переводит статус в `queued` и очищает
  времена и причину отказа. История попыток по одному входу не нужна: важен исход.
- Причина отказа очищается от технических подробностей до записи. Текст исключения `httpx`
  содержит адрес обращения, и он может быть внутренним — то же правило, что для догона.
- Окно, полнота и признак эмуляции **хранятся, а не вычисляются при показе**. Вычисление
  дало бы сегодняшний ответ на вчерашний вопрос: глубина окна — настройка и может
  измениться, полнота входа меняется с приходом данных, а звено ранжирования однажды
  перестанет быть эмулятором. Прогон описывает то, что было, и эти три величины — часть
  того, что было.
- `emulated` заполняется из ответа звена, а не выводится из имени модели: звено само
  объявляет себя эмулятором, и догадка по имени разошлась бы с правдой молча.

## 2. Результат ранжирования (`daily_ml_ranking_item`)

Строки выдачи, принадлежащие прогону. Хранятся, потому что набор удаляется через 30 дней, а
решение должно оставаться воспроизводимо читаемым.

| Поле | Тип | Смысл |
|---|---|---|
| `run_id` | ссылка | Прогон, к которому относится строка |
| `rank` | целое | Место в порядке, начиная с 1 |
| `asset_id` | строка | Экономический актив |
| `price_series_id` | строка | Ценовой ряд |
| `score` | `NUMERIC(28,9)` | Скор модели |

**Ограничения**: первичный ключ `(run_id, rank)`; индекс по `(run_id, asset_id)`.

**Правила**

- Скор передаётся строкой и хранится с исходной точностью: он участвует в сортировке, и
  `float` сделал бы порядок зависимым от представления.
- Скор **не сравнивается между датами**: он задаёт порядок внутри одной даты решения.
  Это свойство модели, и интерфейс обязан о нём говорить.
- Строки записываются одной транзакцией вместе с переводом прогона в `success`: половина
  выдачи хуже её отсутствия.

## 3. Размер лота (`market_asset.lot_size`)

Новая колонка в существующем справочнике активов.

| Поле | Тип | Смысл |
|---|---|---|
| `lot_size` | целое \| null | Минимальная партия торгов на бирже |

**Правила**

- Собирается с биржи вместе с прочими справочниками, в группе `reference`: у лота нет
  истории, это текущее состояние инструмента.
- `null` означает «не получен», а не «единица». Актив без лота в план не попадает, и это
  объясняется.
- На готовность данных лот **не влияет**: он не является входом модели и нужен только
  плану.

## 4. Состояния прогона

```text
        реконсиляция нашла готовую дату без успеха
                          │
                          ▼
                       queued ─────────────────┐
                          │ обработчик взял    │ worker перезапущен
                          ▼                    │
                       running                 │
                  ┌───────┴───────┐            │
             ответ ✓          ошибка ✗         ▼
                  ▼               ▼         failed
               success         failed ◄────(прервано)
                                  │
                                  │ повтор: attempt+1
                                  └──────► queued
```

Четыре состояния, и каждое описывает **сам прогон**:

| Не состояние | Чем является |
|---|---|
| Пауза | Настройка автоматического режима. Второе место для неё разошлось бы с первым |
| Устаревание входа | Отношение прогона к текущим данным; вычисляется, а не хранится |
| «Уже посчитано» | Отсутствие работы. Строка на каждую холостую проверку утопила бы историю |
| Отмена | Не заводится: инференс длится секунды. Появится вместе с длинной моделью |

**Правила переходов**

- В `running` переходит только обработчик очереди, держащий блокировку.
- `running`, обнаруженный при старте, означает обрыв: переводится в `failed` с причиной
  «прервано перезапуском» и возвращается в очередь.
- Пауза не отменяет выполняющееся задание: оно доводится до конца, новые не создаются.

## 5. Готовность данных за дату (вычисляется)

Дата **готова**, когда выполнено всё:

1. дата является торговой сессией;
2. по каждой **обязательной** группе в её окне нет пропущенных сессий;
3. по каждой обязательной группе нет незакрытых источников;
4. набор за эту дату строится, и объявление неполноты по обязательным группам пусто.

Первые три проверки дешёвые и выполняются на каждом тике. Четвёртая — фактическая сборка
набора — выполняется только перед запуском прогона, и её слово окончательно: именно набор
уходит модели, и его объявление полноты входит в дайджест.

**Инвариант**: Daily ML не запускается на неполном обязательном окне ни при каких условиях.

**Перечень обязательных групп** — конфигурация. Дивиденды в него не входят: они не являются
входом модели.

## 6. Устаревший вход (вычисляется)

Прогон устарел, если дайджест набора, который построился бы за его дату **сейчас**,
отличается от сохранённого.

| Случай | Поведение |
|---|---|
| Историческая дата | Признак показывается, автоматического пересчёта нет |
| Последняя готовая дата | Выполняется новый прогон автоматически |

Почему не хранится: закрытие одной исторической дыры меняет дайджест каждой даты, в чьё
окно эта сессия входит — до 314 записей. Хранимый признак пришлось бы обновлять пакетом и
он расходился бы с фактом; вычисляемый не может.

Считается лениво: в списке истории он не нужен, при открытии прогона — нужен.

## 7. План портфеля (вычисляется, не хранится)

Портфель меняется непрерывно, поэтому сохранённый план устарел бы в момент записи. План
считается по запросу.

**Входы**

| Вход | Источник |
|---|---|
| Порядок активов | Последний успешный прогон |
| Текущие позиции и деньги | Сохранённое состояние счёта |
| Цены | Закрытие последней торговой сессии |
| Размеры лотов | Справочник активов |
| Правило, лимит, комиссия | Настройки человека |

**Правила распределения** (перенесены из исследования):

| Правило | Веса |
|---|---|
| Равные доли по первым k | `1/k` каждому, k из набора 20, 30, 50, 100, 150 |
| Диапазоны рангов 1–100 | 1–20 → 0,2403; 21–30 → 0,1063; 31–50 → 0,2039; 51–100 → 0,4495; внутри диапазона поровну |

**Арифметика**

1. Инструменты вне вселенной модели — облигации, денежный фонд — переносятся как есть и в
   расчётный капитал не входят.
2. Расчётный капитал = деньги + текущая стоимость акций, но не больше заданного лимита.
3. Целевая сумма актива = расчётный капитал × вес.
4. Количество = целое число лотов, не превышающее целевую сумму.
5. **Остаток от округления и вес недоступного актива остаются деньгами** и между другими
   активами не перераспределяются. Правило перенесено из ребалансировки исследования, где
   записано явно: иначе доли исказятся относительно правила.
6. Комиссия применяется к каждой стороне — и к покупке, и к продаже.
7. Разница к текущим позициям показывается в штуках и в деньгах.

**Отказы расчёта**

| Условие | Ответ |
|---|---|
| Нет успешного ранжирования | Плана нет, сказано чего дождаться |
| Ранжирование устарело | Плана нет: решение относится к другим данным |
| Счёт не подключён | Плана нет: неизвестны деньги и позиции |
| Снимок счёта устарел | Плана нет: расчёт по устаревшему остатку вводит в заблуждение |
| Активов меньше, чем требует правило | Плана нет, названо требуемое и доступное число |
| У актива нет цены или лота | Актив исключается из плана с объяснением |

**Границы**: расчёт не меняет портфель, не выставляет заявок и не обращается к брокеру.
План — утверждение о желаемом состоянии, а не приказ.

## 8. Что меняется в существующих данных

| Место | Изменение |
|---|---|
